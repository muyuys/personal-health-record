# 023 病历信息架构整合（统一时间轴 + 导航分组 + 用药页去重）

- 优先级：P1（用户明确诉求：功能已丰富但有重叠，想简化；本卡为**信息架构(IA)简化**，不动数据模型）
- 背景 / 决策依据：
  - 用户问"就诊记录、检查时间线、用药记录 其实都是病历，是不是可以直接合并？"
  - 产品结论（见专家评估）：**不建议合并成单一"病历"实体**。三者是**正确的三层领域分层**——`visit` 是"点事件"（某次就诊快照，主键 `visit.id`）、`medication` 是"线段"（药物跨期持续，`status` active/stopped/unknown，`visit_id` 为**可空可选**外键，可横跨多次就诊或无就诊归属）、`timeline` **不是表**，是从静态档案 + 运行时 visits 拼出的**只读聚合视图**（还含"照片归档""舌苔照片"等非就诊非用药事件）。
  - 用户"重叠感"的真实来源＝**入口分散 + 用药页静态/结构化双份并存**，不是数据重复。故方向＝**简化 IA，保留数据分层**。
- 目标：在**不改数据库 schema、不改 `/api/*` 契约、不做数据迁移**的前提下，消除入口重叠、建立唯一"病历总时序"入口、导航降噪。
- 范围：
  - **P0-a 用药页去重**：`js/app.views.health.js` `renderMeds` 中并存的旧静态档案 `ARCHIVE.meds.current/history`（约 774–806 行）收敛为只读、默认折叠的"历史对照"，或数据迁完后移除；不得两套并排平铺。
  - **P0-b 时间线总入口**：`renderTimeline`（`js/app.views.health.js` ~709 行，已并入 `visits`）补全为也并入 `medications` 的起止事件点（以 `startDate` 作为事件日期、`visitId` 作关联）；纯前端聚合，不建表。
  - **P1-a 统一时间轴主键口径**：确立事件归一化结构 `{id, date, type, href, src}`——`visit` 用 `id/date`；`medication` 用 `startDate` 作事件点、`visitId` 关联；timeline 静态事件补稳定 key（`date+src` 哈希）。各视图只读 `visit.reportId`、`medication.visitId` 两个权威外键，不再各自另拼。
  - **P1-b 交叉引用一致化**：摘要 / 时间线 / 详情页统一读同一关联口径。
  - **P2 导航分组**：侧栏 NAV（`js/app.views.health.js` ~2–15 行）现有多项，"检查时间线 / 就诊记录 / 用药记录"收进一个"病历"父分组 + 子视图；路由（`js/app.boot.js` ROUTES）与后端不变。
  - 可选：就诊详情页内联展示该次用药 + 该次检验（复用 `renderSummary` 已有聚合逻辑），减少跨页跳转。
- 验收：
  - 用药页不再"结构化表 + 旧静态档案"两套平铺；旧档案以折叠对照呈现或已移除。
  - 存在唯一"病历/时间线"总视图，就诊与用药事件均按日期出现并各自可回链详情。
  - 侧栏出现"病历"分组（含时间线/就诊/用药子项），NAV 视觉项减少；所有原有路由仍可达、链接不 404。
  - **数据库表结构、`/api/all`、`/api/history`、`/api/import`、导入导出格式全部不变**；`data/health.db` 无迁移。
  - `node --check` 全部 JS 通过；页面 200；主要视图（时间线/就诊/用药）渲染正常。
- 非目标（明确拒绝）：把 `visit`/`medication` 合并为单表或嵌套 JSON；给 timeline 建表；改动 schema 或后端序列化分支。这些属高风险、破坏性、低收益，本卡不做。
- 风险 / 回滚：改动仅限前端渲染与导航 → 可增量、可回滚；如某视图异常，单独回退对应 render 函数即可。
