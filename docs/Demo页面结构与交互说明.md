# 个人健康档案 Demo 页面结构与交互说明

更新日期：2026-11-01。

本文将本次 Demo 的信息架构、页面内容、入口关系和交互规则整理为设计依据，供后续重新设计界面使用。配色、字体、图标、间距、组件外观及具体排版由用户重新设计，不沿用 Demo 的视觉样式作为约束。

本文中的“默认展示、按需展开、主次操作”表达信息优先级；具体使用独立页面、弹层或其他容器，可在视觉设计时调整。

## 1. 产品目标与设计原则

目标：用户可以快速留下有用的健康记录，需要时找得到同一次就诊的相关信息。

- 先记录，再整理，不要求填写前先完成分类或基础资料。
- 默认只展示完成当前任务必需的内容，专业字段按需补充。
- 一段速记可以是一条正式记录，不因缺少选填项一律标为待完善。
- 就诊、报告、用药可以分别记录，在查阅时集中组织。
- 未记录的信息保持未知，不自动补为“无”或推断为诊断。

## 2. 全局导航与页面层级

一级导航固定为五个模块，各模块内部再组织记录类型和工具。

| 一级模块 | 默认内容 | 下级内容 |
| --- | --- | --- |
| 首页 | 快捷记录、待办、最近记录 | 记一笔选择页、全部待办 |
| 就医记录 | 综合时间线 | 全部 / 就诊 / 报告 / 用药；记录详情；就诊摘要 |
| 日常健康 | 最近使用的记录类型，初次默认体重与饮食 | 体重与饮食 / 血压等体征 / 症状 / 睡眠 |
| 健康主题 | 主动关注的健康问题 | 某主题关联的就诊、报告、症状、计划 |
| 我的 | 资料和数据管理 | 基础资料、重要过敏信息、备份与恢复、设备数据导入、存储位置、帮助 |

桌面和移动端使用同一套模块。移动端可将五个模块放在底部导航；桌面可用侧栏。“待办”从首页进入，不额外增加一个一级模块。

辅助页面及入口关系：

| 页面 | 进入方式 | 返回位置 |
| --- | --- | --- |
| 记一笔选择页 | 首页“记一笔” | 首页 |
| 记一次就诊 | 首页快捷入口、记一笔、就医记录页 | 发起记录的页面 |
| 存一份报告 | 首页快捷入口、记一笔、报告列表 | 发起记录的页面 |
| 就诊详情 | 最近记录、就医记录列表 | 原列表，保留筛选条件 |
| 待办与提醒 | 首页“全部待办”、就诊详情中的提醒入口 | 原页面 |
| 就诊摘要 | 就诊详情、就医模块工具入口 | 原页面 |

## 3. 首页

内容按以下优先级组织：

| 区域 | 内容 | 操作与规则 |
| --- | --- | --- |
| 页面标题与全局操作 | 健康档案、搜索、记一笔 | 搜索覆盖记录文字、报告名称、医院、药物、指标；记一笔打开类型选择 |
| 快捷记录 | 记一次就诊、存一份报告、记日常数据 | 直接进入对应流程，不先要求选择所属板块 |
| 接下来要做 | 到期或主动置顶的提醒，最多三项 | 显示日期、内容、完成操作、全部待办入口；没有待办时隐藏 |
| 最近记录 | 最近三条记录，按事件时间倒序 | 显示类型、日期、摘要；点击打开对应记录；新保存的记录立即可见 |
| 我关注的，可选 | 用户主动选择的主题或指标 | 最多两个，默认不设置；不固定展示减重数据 |

新用户无数据时，保留三个快捷入口，最近记录展示简短引导。不展示虚构记录，不要求先补齐整份健康档案，不展示全档完整度百分比。

## 4. “记一笔”选择页

该入口不默认进入体重表单，先让用户明确本次要记录什么：

| 选项 | 辅助说明 | 下一步 |
| --- | --- | --- |
| 一次就诊 | 日期 + 一段记录 | 就诊速记 |
| 一份报告 | 先保存原件 | 报告采集 |
| 日常数据 | 选一种，马上记 | 日常健康中的类型选择 |

在就医或日常模块内点击明确的记录按钮时，直接打开对应表单，不再重复选择类型。

## 5. 记一次就诊

### 5.1 默认展示

| 内容 | 默认值 / 提示 | 必填规则 |
| --- | --- | --- |
| 标题 | 记一次就诊 | — |
| 说明 | 记得多少写多少，以后随时可以补充 | — |
| 就诊日期 | 今天，可修改 | 必须有有效日期 |
| 自由记录 | 这次看病，记下什么？ | 自由记录、有效附件或专业内容至少有一项 |
| 输入提示 | 看病原因、医生怎么说、下一步安排；也可以直接粘贴病历 | 不强迫拆分内容 |
| 主要操作 | 保存记录 | 保存成功后返回来源页 |

### 5.2 按需补充

以下区域默认折叠，展开与收起保留已输入内容。

| 区域 | 字段 / 操作 | 规则 |
| --- | --- | --- |
| 补充就诊信息 | 医院、科室、医生、就诊类型 | 均为选填；类型默认门诊，并在折叠摘要中提示，可改为急诊、住院、体检、线上问诊、其他 |
| 补充诊断与医嘱 | 就诊原因、医生明确诊断、医嘱 | 按已知内容填写；自由记录不自动成为确诊 |
| 添加资料 | 拍照、选择文件、关联已有报告 | 有原件即可先记录；不要求先识别或录完指标 |

### 5.3 保存、退出与编辑

- 最低保存条件：有效日期，加非空自由记录、有效附件、就诊原因、医生诊断或医嘱中的至少一项。只选日期不生成空记录。
- 保存成功：回到发起页面，新记录立即出现，提示“已保存”，可查看记录。
- 后续动作：在记录详情中可加复诊提醒、记本次用药；保存后不连续弹出必填流程。
- 保存失败：保留文字、已选资料和展开状态，提示重试，不显示成功。
- 有未保存内容时离开：提供继续填写与放弃本次内容的选择。
- 编辑已有记录：保留已有结构化信息与关联资料，收起字段不等于清空字段。

## 6. 存一份报告

流程：添加原件 → 保存原件，或按需确认信息 → 可选提取文字与指标 → 查阅或关联就诊。

| 信息 / 操作 | 优先级 | 规则 |
| --- | --- | --- |
| 报告原件 | 核心 | 拍照或选择文件；不依赖 OCR 成功 |
| 日期 | 可确认或暂缺 | 不确定时标为日期待确认，不用今天代替报告日期 |
| 名称、机构、类型 | 选填 | 能确认再补充 |
| 从图片提取文字 | 可选 | 提供原图与识别结果核对；确认后填入，不覆盖已有内容 |
| 提取检验指标 | 可选 | 核对后纳入指标记录，保留原件来源 |
| 关联就诊 | 可选 | 用户明确选择，不能只因同一天就自动关联 |

独立报告不要求新建一次就诊。日期未确认的报告单独标识，不按虚构日期插入时间线。

## 7. 就医记录列表

- 默认显示综合时间线，提供全部、就诊、报告、用药四种筛选。
- 同一页面内按记录类型查看，不另设一个需要手动维护的时间线模块。
- 每条记录包含：日期、类型、标题或一句摘要、资料数量、来源。
- 点击记录进入对应详情，编辑、删除等次要操作在详情或更多操作中提供。
- 可按文字和日期查找；切换筛选、进入详情再返回时保留上下文。
- 新录入内容与历史档案均能查到，同一来源避免重复呈现。
- 无数据时说明本类型的用途，并给出一个明确的新增入口。

列表不限定必须使用卡片或表格；视觉设计需保证移动端易读，不依赖横向滚动完成核心操作。

## 8. 就诊详情

详情页按以下信息顺序组织：

| 区域 | 内容 | 主要操作 |
| --- | --- | --- |
| 就诊概况 | 日期、类型、已填医院与科室 | 编辑记录 |
| 本次记录 | 完整自由记录 | 修改或补充 |
| 关联资料 | 病历、报告及原件 | 查看原件、添加、关联已有资料 |
| 本次用药 | 与本次就诊明确关联的药物 | 添加或关联用药 |
| 下一步安排 | 复诊、复查等用户记录的安排 | 加提醒、查看提醒 |
| 详细信息 | 医生、就诊原因、明确诊断、医嘱等 | 按需展开和编辑 |
| 就诊摘要 | 选定记录及相关重要信息 | 先预览，再导出给医生 |

未填写内容显示“未记录”或“未添加”。本次就诊用药与当前全部用药分别标注，不把所有在服药物自动算作本次处方。新增就诊不自动更改药物状态。

## 9. 日常健康

同一模块包含四个二级类型，每个类型内同时提供记录与趋势回看。

| 类型 | 默认记录内容 | 按需补充 |
| --- | --- | --- |
| 体重与饮食 | 日期、体重、测量条件；饮食另按餐记录 | 体脂、围度、其他体成分；不默认把体重都算作晨重 |
| 血压等体征 | 日期、体征类型与对应测量值 | 时段、心率、测量条件、备注；选血压时填写收缩压与舒张压 |
| 症状 | 日期、哪里不舒服或一句描述 | 程度、诱因、照片、主题 |
| 睡眠 | 最近睡眠记录与设备导入入口 | 需要手动记录时，再补入睡、起床和主观感受 |

初次进入默认体重与饮食；以后记住最近使用的类型。不把全部记录类型的表单同时平铺。

## 10. 健康主题

主题用于长期回看某个问题，不作为任何录入流程的必选项。

- 主题列表：显示用户关注的问题、最近记录、当前跟进状态。
- 主题详情：集中查看相关就诊、报告、症状和计划，保留原始来源。
- 记录可以稍后归入主题；不强迫首次记录时先建主题。
- 尚无主题时说明用途，不生成占位疾病，不把缺少诊断视为确诊。

## 11. 待办与提醒

- 入口：首页“全部待办”、就诊详情中的“加复诊提醒”。
- 最少输入：提醒内容；日期可不填。
- 可选信息：提醒类型、关联记录、重点标记。
- 类型包括复诊、定期检查、复查化验和其他。
- 有日期的提醒按到期状态组织；无日期的提醒不显示逾期。
- 支持查看、完成、编辑；不从含糊医嘱中自动生成确定的复查日期。

## 12. 我的

| 分区 | 内容 |
| --- | --- |
| 个人信息 | 基础资料、重要过敏信息、相关既往史 |
| 备份与恢复 | 导出完整备份、恢复备份 |
| 设备数据 | 导入体重、睡眠等设备数据 |
| 存储与帮助 | 当前保存位置、存储状态、使用帮助 |

“存报告”“导入设备数据”“恢复备份”使用独立入口和明确名称。当前存储位置发生变化或保存异常时，在相关操作处提示。

## 13. Demo 已展示的范围

这份说明同时包含 Demo 已演示的结构与完整产品应遵循的规则，后续设计时需区分：

| 范围 | Demo 当前表现 |
| --- | --- |
| 一级导航、首页、记一笔 | 可切换，展示主要信息层级和入口 |
| 门诊速记、选填区域 | 可输入、展开、演示保存，并在最近记录与就医列表查看 |
| 就诊详情 | 展示本次记录、资料、用药、下一步安排与详细信息的顺序 |
| 报告采集 | 使用示例原件演示保存，不读取实际文件 |
| 日常健康、主题、我的 | 展示模块结构，详细表单和管理功能未展开 |
| 提醒 | 演示入口与完成状态，新增提醒尚未形成完整表单 |
| 搜索、OCR、真实附件、编辑、导出、失败处理、离开确认 | 属于产品规则，Demo 未完整实现 |

Demo 中的数据仅存在当次预览的内存中，刷新后消失。示例文案和占位资料不代表真实档案；Demo 的交互简化不替代本文规定的产品规则。

## 14. 后续设计检查清单

- 首页能直接找到记就诊、存报告、记日常三个入口。
- 门诊表单首次打开只需理解日期和自由记录，选填区域不会造成填写压力。
- 一句话或一份原件能留下记录，保存后找得到。
- 能从一个就诊详情查看相关资料、用药和下一步安排。
- 不需要补齐全部个人资料，才能开始使用。
- 无数据、日期不确定、未填写诊断、识别失败等状态都有明确表达。
- 核心动作在手机上可完成，导航与桌面含义一致。
- 视觉设计可独立调整，不改变上述信息层级和关键业务规则。
