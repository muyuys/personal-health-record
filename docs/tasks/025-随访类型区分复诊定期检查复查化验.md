# 025 随访类型：待办区分「复诊 / 定期检查 / 复查化验 / 其他」

- **优先级**：P1
- **类型**：数据字段 + 前端渲染 + 后端持久化（小增量、幂等迁移）
- **关联**：016（提醒/通知）、015（页内可编辑）、023/024（信息架构整合）

## 背景与决策

当前「复诊待办」把**所有随访类待办**都笼统叫「复诊」，但实际医学随访分几类，语义不同：

- **复诊**：门诊/急诊随访，医生当面看结果、调整方案（如足踝门诊、眼科复诊）。
- **定期检查**：影像、功能、体检类定期复查（如定期 CT/MRI、眼底、听力）。
- **复查化验**：定期抽血/尿检等实验室复查（如肝肾功能、血脂、尿酸）。
- **其他**：用药核对、取药、资料补齐等非就诊随访。

**问题**：页面标题「复诊待办」、导航、首页提醒文案（`buildReminders` 的 `kind:'followup'`）一律用"复诊"措辞，与"定期检查/化验"语义不符，易误导（用户原话 m01801："不是所有的科室都需要复诊的，有些是定期检查"）。

**决策：引入「随访类型」字段 `followType`，全面区分四类。** 统一为中性主题「随访与待办」，页内按类型区分/标注，提醒文案按类型措辞。**不改变底层"待办是一张表"的模型**（同 023/024：是语义标注，不是拆实体）。

- 类型取值（代码常量 `FOLLOW_TYPES`）：
  - `visit` 复诊（默认）
  - `exam` 定期检查
  - `lab` 复查化验
  - `other` 其他
- 缺省：老数据无 `followType` 视为 `visit`（复诊），保持兼容、无需强制回填。

## 范围

**做**（贯穿 5 层，保持一致）：

1. **数据字段**
   - `js/app.core.js`：新增常量 `FOLLOW_TYPES = [{k:'visit',label:'复诊'},{k:'exam',label:'定期检查'},{k:'lab',label:'复查化验'},{k:'other',label:'其他'}]` 与 `followTypeLabel(k)`（未知→'复诊'）。
   - `normTodoItem`(:620) 增加 `followType: FOLLOW_TYPES.some(t=>t.k===x.followType)?x.followType:'visit'`。
   - 静态待办 `assets/data.js` todos items 补 `followType`：`t-eye`→`visit`（眼科复诊）、`t-ankle`→`visit`、`t-med`→`other`、`t-lab`→`lab`（肝肾功能化验核对）、`t-these/t-base`→`other`、减重组 4 项→`other`。静态项不写 `followType` 也应默认 visit，故只给非 visit 的显式标注更稳妥（避免 data.js 全量改动）。

2. **后端持久化**（`server/health_server.py`）
   - `todo_item` 表：`CREATE TABLE` 加 `follow_type TEXT DEFAULT ''`（新库）；`init_db` 幂等迁移 `ALTER TABLE todo_item ADD COLUMN follow_type TEXT DEFAULT ''`（老库）。
   - `get_all()` 的 todo_items SELECT 加 `COALESCE(follow_type,'') AS followType`。
   - `replace_todo_items()` INSERT 列增加 `follow_type`（读 `r.get('followType','')`）。
   - 其余 schema/接口契约不变；禁 DROP。

3. **表单**（`js/app.boot.js` `openTodoForm` :798）
   - `r` 默认加 `followType:'visit'`；表单加一个「随访类型」`<select name="followType">`（选项按 `FOLLOW_TYPES`）。
   - submit 的 `obj` 加 `followType: normFollowType(fd.get('followType'))`（或直接取合法值否则 visit）。
   - 弹窗标题/说明把"复诊待办"改中性："随访与待办"。

4. **列表渲染**（`js/app.views.health.js` `renderTodos` :887）
   - `setHead` 标题由「复诊与待办 / 复诊待办」改「随访与待办 / 随访与待办」（eyebrow 可 `FOLLOW-UP　随访与待办`）。
   - 每条待办（静态 + 用户新增）旁显示类型 chip（复诊/定期检查/复查化验/其他），用现有 `.chip` 样式；不同类型可给不同色调类（如 exam=green、lab=amber、visit=默认、other=mute）。
   - 页面说明文案避免"复诊"泛化，改为"就诊/检查/化验的随访事项"。

5. **提醒文案**（`js/app.derive.js` `buildReminders` :301）
   - `kind:'followup'` 的提醒 title/sub 前缀按 `followTypeLabel` 反映类型，例如 sub 或 title 上标「复诊 / 定期检查 / 复查化验 / 其他」，不再一律"复诊"。到期/临近逻辑与排序不变。
   - 红点计数 `reminderCountByPage` 不变（仍按 page 计）。
   - `reminderBandHTML` 无需改结构。

6. **静态文案**（`assets/data.js:53` `followup:{label:'待复诊',...}`）建议改为「待随访」（issue status 显示的语义更中性）；若改动牵连其它状态文案，可在任务内统一。

7. **任务卡与文档**：更新 `docs/tasks/README.md` 索引加 025。

**不做（非目标）**：

- 不拆分 todo_item 为多张表；不改 `state.done` 勾选模型。
- 不改到期提醒的日期计算/阈值（`REMIND_SOON_DAYS=7`）。
- 不改 `/api` 路径与响应外壳结构（仅在 todoItems 元素内多一个 `followType` 字段）。
- 不删旧字段、不 DROP。

## 验收

1. 新增/编辑待办可选「随访类型」四类；保存后刷新仍在（写库往返 `followType` 正确，非 visit 值不被吞成默认）。
2. 列表里每条待办显示正确的类型 chip；无 `followType` 的老数据默认显示「复诊」。
3. 页面标题/导航/提醒文案不再把所有事项叫「复诊」；到期提醒能反映类型（如"定期检查 · 还有 3 天"）。
4. `node --check` 全部 JS 通过；`python` 解析 `health_server.py` 通过；DB 迁移幂等（连续启动两次不报错、不丢数据）。
5. HTTP 冒烟：页面 200；`GET /api/all` 的 `todoItems` 含 `followType`；`PUT /api/history` 往返保留 `followType`。
6. 现有待办数据条数不变、勾选状态不变、`server/health_server.py` 改动仅限 `todo_item` 相关（`follow_type` 列 + SELECT/INSERT）。

## 风险与回滚

- **风险**：老库无列 → 靠 `init_db` 幂等 ALTER 补列；读写都 `COALESCE('')` 防 NULL。
- **风险**：静态 data.js 全量补字段易漏 → 只标非 visit 项，其余靠默认。
- **回滚**：改动集中在 `js/app.core.js`、`js/app.boot.js`、`js/app.views.health.js`、`js/app.derive.js`、`assets/data.js`、`server/health_server.py`；单独 revert 即可（follow_type 列残留无害）。
