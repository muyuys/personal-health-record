# 文档构建说明（md → html）

> 本文件说明如何用**一个入口**把项目里的 Markdown 文档统一渲染为 HTML，替代过去“手工同步 / 经常忘记重新生成”的做法。对应任务 019（可维护性）。

## 一条命令搞定

```bash
# 完整构建：更新「健康问题总表」并重渲染 docs 下全部 .md 与根 README.md
node Tools/build-docs.cjs

# 只检查将处理哪些文件，不写盘、不跑子脚本（适合 CI / 提交前自查）
node Tools/build-docs.cjs --check

# 暂存构建：全部输出写到 build_test/ 下（不改动真实 docs，适合受限环境预览）
node Tools/build-docs.cjs --out=build_test
```

构建是**幂等**的：重复运行结果一致，不会产生重复内容，也不会改动数据库（对 `data/health.db` 只读）。

## 它做了什么

`Tools/build-docs.cjs` 把原先分散的三个脚本收敛为一个可重复运行的入口，按顺序执行：

1. **从数据库派生「健康问题总表」** — 调用 `Tools/生成问题总表.cjs`（只读 `data/health.db` 的 `labs` 表，重写 `docs/健康档案/健康问题总表.md` 里的 AUTO 标记区块与「肝肾功能」行；异常严格按每条记录自身参考区间判定，不臆造）。
2. **补齐主题档案结构** — 调用 `Tools/生成主题档案.cjs`（为 `docs/主题/*` 补齐「主诉 / 诊断 / 诱因 / 当前处置 / 复诊节点」五段并计算「档案完整度」；已有非空文件不加 `--init` 不改动）。
3. **全域渲染 md → html** — 用统一模板把 `README.md` 与 `docs` 下所有 `.md` **强制重新渲染**为同名 `.html`（这一步修复历史上的“md 改了但 html 没跟上”的漂移）。

> 三个原脚本 **保持不变**（可逆、可单独调用）；`build-docs.cjs` 只是它们之上的统一编排 + 全域渲染补充。样式常量（CSS）只有一处来源：`Tools/生成HTML档案.cjs` 里的 `const css = ...`，`build-docs.cjs` 用正则读取它，避免两处 CSS 漂移。

## 覆盖范围与排除

- **纳入渲染**：根 `README.md`，以及 `docs/**/*.md`（含 `docs/健康档案`、`docs/减重记录`、`docs/主题`、`docs/使用指南.md`、`docs/HANDOFF.md` 等）。
- **排除（内部文档，不生成对外页面）**：
  - `docs/tasks/**` — 内部任务说明。
- `docs/健康档案/检验趋势.html` 是**自定义页面**（配套 `检验趋势.css` / `检验趋势.js`，没有对应 `.md`），渲染脚本只处理 `.md`，因此**不会覆盖**它。

## 前端模块拆分与分层（同属任务 019）

`assets/app.js` 已改为**空占位**（仅保留说明注释）；实际逻辑在 `js/` 下，由 `index.html` 按依赖顺序以**经典脚本**加载（无打包器、`file://` 也能打开离线页）。2026-11-01 在“按视图切分”的基础上，又把**纯业务规则**与**存储 I/O** 抽成了独立模块：

| 文件 | 职责 |
| --- | --- |
| `js/app.domain.js` | **纯业务规则**：检验异常判定、定性结果、去重 key、体征参考区间。不碰 DOM / 网络 / localStorage，可 `node require` 直接测 |
| `js/app.storage.js` | **存储与传输适配器**：唯一访问 localStorage / fetch 的前端模块；服务端写入走**有序队列**，入队即做 JSON 快照；失败不阻塞后续重试 |
| `js/app.core.js` | 基础工具 / 图标 / 数据模型与规范化、应用内存状态；经 storage 适配器读写 |
| `js/app.derive.js` | 派生数据 / 提醒 / 档案完整度；领域规则调用 `HealthDomain` |
| `js/app.views.health.js` | 外壳 / 总览 / 健康问题 / 检验指标 / 全部检验 / 时间线 / 用药 / 待办 |
| `js/app.views.body.js` | 减重记录(体脂) / 生命体征 / 睡眠 / 症状 / 减重执行 |
| `js/app.views.profile.js` | 个人资料 / 就诊摘要导出 |
| `js/app.modal.js` | 弹层 / 表单 / 搜索 / 报告原件 / 导入 / OCR |
| `js/app.boot.js` | 事件绑定 / 路由 / 启动 |

**依赖方向**：`domain` ← `core/derive` ← `views/modal` ← `boot`；`storage` 只被 `core` 使用。业务规则不得反向引用页面或存储。

- `index.html` 末尾按上表顺序加载（`assets/data.js`、`assets/parse.js` 仍在前面）。
- 迁移期视图仍通过全局兼容别名（`labs`、`state` 等）共享内存状态——这是**下一阶段的改造点**（见任务 020），不要新增跨模块的全局可写状态。
- 改动某个视图时只改对应 `js/app.*.js`；领域规则改动必须跑 `node Tools/test-domain.cjs`，存储改动必须跑 `node Tools/test-storage.cjs`。

## 服务端分层（2026-11-01）

`server/health_server.py` 现在只是**组合根 + HTTP 路由 + 安全边界**，不再直接写 SQL：

| 文件 | 职责 |
| --- | --- |
| `server/health_repository.py` | SQLite schema/迁移、全部查询与整表替换、报告文件落盘、导入导出；路径由构造注入，可独立实例化测试库 |
| `server/health_backup.py` | SQLite 一致快照、滚动保留 |
| `server/local_http.py` | Host / Origin 同源校验与 CORS 响应头 |
| `server/ocr_server.py` | OCR 引擎适配；对外暴露 `status()` / `recognize_lines()`，其它模块不再读私有全局 |

安全边界：**只允许同源页面访问 API**；`file://` 仅作离线应急，不调用本机服务；静态托管采用白名单（`index.html` / `assets` / `js` / `docs` / 原件路由），数据库、备份、`private_data`、`.git` 等一律不经 HTTP 暴露。

## 依赖说明（应用零依赖，工具链可选）

- **应用运行不需要 npm**：`index.html` + `js/` + `assets/` + Python 服务即可，双击 bat 就能用。
- **文档构建**需要 `marked`，**浏览器 e2e** 需要 `playwright`，两者已在根目录 `package.json` 的 `devDependencies` 中显式声明。换电脑后在项目根目录执行一次：
  ```bash
  npm install        # 只装开发依赖；不装也不影响档案应用本身
  npm run build:docs # 完整文档构建
  npm run check:docs # 只检查将处理哪些文件（不需要 marked，也不写盘）
  npm test           # 快速回归：parse + domain + storage + 后端 13 项
  ```
- `Tools/load-marked.cjs` 统一负责解析 `marked`：本地 `node_modules` → `NODE_PATH` → 历史托管路径（仅兼容兜底）。不要再把某台机器用户目录下的绝对路径写进脚本。

## 受限环境提示（沙箱 / 低权限账户）

若运行账户**对已存在的 `docs` 文件没有写权限**（Windows 上报 `EPERM` / `EACCES`），脚本会**跳过该文件并打印 `[跳过] 无写权限`**，不会中途崩溃。此时可：

- 用 `--out=<目录>` 把结果产出到暂存目录预览；或
- 在具备正常写权限的账户 / 本机正常环境下运行 `node Tools/build-docs.cjs`。
