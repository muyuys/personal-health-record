# 026 · 新版 UI 视觉规范

版本：v1.2（2026-11-01）。适用范围：`index.html` 外壳 + 五个一级页面 + 表单/弹层/列表。
v1.1 变更：按 027 定稿同步 4 处组件变化（历史档案卡、同日提醒标题变体、内层 3 chip、折叠区状态说明行）；措辞统一「报告」；完整度禁止扩展到环形/仪表盘/进度条。
v1.2 变更：实底主色终裁为**页头「记一笔」**（三卡全部描边 + `记一次就诊` 淡绿弱强调）；空库首页最近记录位去掉主按钮；深绿纪律由「6% 面积」改为「全屏只允许 1 个实底按钮」。详见 §12 末尾「v1.2 变更」。
依据：[个人健康档案体验重设计](../个人健康档案体验重设计.md)、[Demo 页面结构与交互说明](../Demo页面结构与交互说明.md)。
方向：**延续暖纸 + 深松绿，做精修**（用户已拍板，不推翻）。
本文只写规范，不改任何 `.html/.css/.js`。所有色值、字号、间距可直接抄进 CSS。

## 0. 三个关键决策（先说结论，后面全部围绕这三条展开）

### 决策 1：卡片去掉阴影，改用「纸色分层 + 1px 描边」

现状 `.card` 是 `background:#FFFFFF` + `box-shadow: 0 1px 2px …, 0 8px 24px …`。问题不是不好看，是**在暖纸底上用白卡 + 阴影，层级靠模糊而不是靠边界**：屏幕上卡片边缘永远发灰，打印和低亮度下更脏。

改成三层纸底 + 描边。实测对比度：

| 组合 | 对比度 | 结论 |
| --- | --- | --- |
| 卡片底 `#FDFBF6` vs 页面底 `#F1EDE4` | **1.13 : 1** | 人眼在静态屏上可靠分辨边界的阈值约为 1.1:1，1.13 处在「勉强能感到、但不敢确定」的区间 → **单靠底色分不出卡片** |
| 描边 `#E4DED0` vs 卡片底 `#FDFBF6` | **1.30 : 1** | 能看见，但不抢眼，这是「安静的边界」 |
| 4% 黑色阴影在纸底上的有效色差 | 约 **1.02 : 1** | 基本不可见，等于白花性能 |

所以：**描边负责边界，底色负责层级，阴影只留给真正浮起来的层（弹层/下拉/提示）**。卡片默认 `box-shadow:none`。

### 决策 2：重推墨色阶梯，消灭 2.8:1 的「说明文字」

现状实测（对比度，来自 WCAG 2.1 公式，背景取实际渲染底色）：

| 现有 token | 值 | 在纸底 `#F2EFE8` | 在白色 | 现状用途 | 判定 |
| --- | --- | --- | --- | --- | --- |
| `--ink` | `#1B1E1B` | 14.65 | 16.83 | 标题 | 过强，纯黑偏冷 |
| `--ink-3` | `#3D463D` | 8.54 | — | 次要正文 | 可用 |
| `--muted` | `#6C736A` | **4.25** | 4.89 | 说明 | **在纸底不达标** |
| `--muted-2` | `#8C9188` | **2.80** | 3.22 | `.page-sub` `.rp-meta` `.task-meta` `.event-meta` | **严重不达标，且用在 10–12px 小字上** |
| `--muted-3` | `#A5AA9F` | **2.07** | 2.37 | `.hint` 时间戳 | **不可读** |
| `--warn` on `--warn-bg` | `#A9583C` / `#F7EAE4` | **4.30** | — | 危险 chip | 差一点，小字不达标 |
| `--amber` on `--amber-bg` | `#A9752F` / `#F3EEE1` | **3.44** | — | 待办 chip | 不达标 |

新版把墨色重排为 5 档，**信息性文字只能取 1–4 档，第 5 档只允许做占位符**。同时把灰阶的色相往松绿偏一点（饱和度约 4%），让灰阶和主色同族，不再出现「暖纸配冷灰」的脏边。

### 决策 3：全屏只有 1 个实底深绿，且它给页头「记一笔」；三张快捷卡全部描边

- 页头「记一笔」是实底主按钮（`--pine-700` + `--on-pine` 文字）。这是**全屏唯一的实底绿**。
- 首页三张快捷卡全部改为**描边卡**（`--bg-card` + 1px `--line`），其中「记一次就诊」用 `--pine-050` 底 + `--pine-100` 描边做**弱强调**（重半档，但离实底还差很远）。
- 理由一（team-lead 终裁）：产品文档 §4 把三个动作**并列**列出（记一次就诊 / 存一份报告 / 记日常数据），给其中任何一个铺实底，等于替用户决定「先记就诊」；而「收到报告就先存原件」同样是核心场景。实底留给页头那个通用入口，三个动作卡保持同级，层级反而更干净。
- 理由二：一屏两个实底会互相削弱。用「面积 + 淡色底」vs「小面积实底」区分主次，而不是叠两块主色。
- **已终裁，不再有备选方案。** 不要再反向调整为「实底给快捷卡」——这是本轮唯一被反复过的决定，改一次要动 026 §0/§5.1/§7/§11 与 027 §1.3 五处。

## 1. 色彩系统

### 1.1 分层底色（纸的三层 + 一个纯白白名单）

| token | 值 | 用途 | 禁止用法 |
| --- | --- | --- | --- |
| `--bg-page` | `#F1EDE4` | 页面底、`body`、rail 之外的主区 | 不要用纯白 `#FFF` 做页面底（理由见下表下方）；不要用它做输入框底 |
| `--bg-card` | `#FDFBF6` | 所有卡片、列表容器、表单容器底 | 不要给卡片加阴影；不要用它做弹层底（弹层要更亮一档） |
| `--bg-raise` | `#FFFFFF` | **仅**：弹层/底部抽屉、下拉与自动补全面板、分段控件滑块、报告原件缩略图底 | 不要用它做页面底或普通卡片底 |
| `--bg-sunken` | `#EBE6DA` | 内嵌下沉区：分段控件轨道、表头、代码块、只读字段、禁用输入框 | 不要用它做正文容器底（会和页面底糊在一起） |
| `--bg-hover` | `#F7F3EA` | 列表行 hover、导航 hover、折叠头 hover | 不要用它做选中态（选中要更明确，见 1.4） |
| `--bg-selected` | `#E7EFE8` | 导航当前项、主题卡选中、列表选中行 | 不要用它做大面积区块底 |

**为什么页面底不能用纯白**（写进评审材料的理由，三条，都可验证）：

1. **眩光**：`#FFFFFF` 与正文 `#191F1B` 对比 16.76:1，在 250–350 nits 的普通笔电屏上，中文小字会因过曝产生笔画粘连感；`#F1EDE4` 与正文对比 14.34:1，同样清晰但边缘更干净。
2. **三层压不出来**：页面白 + 卡片白 = 只能用阴影分层，而阴影在纸底上的有效色差只有 1.02:1（见决策 1），等于没分。纸色分层不依赖亮度环境，白天晚上都成立。
3. **语义**：这是一份「纸质病历」，暖纸底把这个隐喻直接画出来；纯白底会把它拉回「后台管理系统」。这也和「不堆指标、不做健康评分」的产品调性一致。

**为什么卡片必须有 1px 描边**：卡片底与页面底只差 1.13:1。没有描边时，卡片边界依赖屏幕伽马和观看角度，同一份设计在不同设备上「有没有卡片」会得出不同结论。描边 `#E4DED0` 相对卡底 1.30:1，是一个恒定、可预期的边界，且成本为 0（不用阴影模糊、不用合成层）。

### 1.5 状态色（6 种状态 + 1 类中性信息，全部实测达标）

每种状态固定「底 / 字 / 点」三元组。**状态色只出现在 chip、圆点、左侧 2px 色条、图标上，不给整行或整卡上色。**

| 状态 | 底 `bg` | 字 `fg` | 点/图标 | 实测对比（fg on bg） | 用在什么上 | 禁止用法 |
| --- | --- | --- | --- | --- | --- | --- |
| **记录中 / 监测中**（在服药物、跟进中的主题、持续观察的指标） | `#E6EFE8` | `#2C5B44` | `#2F6B57` | **6.65 : 1** | 用药「在服」chip、主题「跟进中」chip | 不要给卡片整块铺这个绿；不要用它表示「成功」 |
| **待复诊 / 待办**（有日期的未到期提醒） | `#F5EBD6` | `#7A561A` | `#A9752F` | **5.59 : 1**（点 3.44，仅做圆点，不承载文字） | 待办 chip、复诊提醒、报告「日期待确认」 | 不要用琥珀做大面积底；**逾期不要用琥珀**（见下） |
| **待补充**（用户点了「稍后整理」，或原件已存但信息未确认） | `#F1EEE6` | `#5C645C` | 无点，用 **1px 虚线描边** `#D4CCBA` | **5.28 : 1** | 「待整理」chip、日期未确认 | **不要给这类打彩色**——它是「用户主动推迟」，不是问题。用虚线表达「未闭合」即可 |
| **历史 / 已完成**（已停用药、已完成提醒、既往记录） | 透明（无底） | `#5C645C` | 1px 实线 `#E4DED0` | 5.92 : 1（在卡底） | 「已停用」「已完成」chip | 不要用删除线表达「历史」（删除线只用于待办完成） |
| **异常**（检验超参考范围、血压超范围、危急过敏） | `#FAEAE3` | `#8E3A28` | `#8E3A28` | **6.44 : 1** | 异常值标记、危急过敏提示条 | **不要用纯红**（`#E53935` 这类在暖底上会发紫）；不要给「未记录」用这个色（未记录≠异常） |
| **危险 / 失败**（保存失败、写入错误） | `#F7DFD7` | `#83301F` | `#83301F` | **6.85 : 1** | 保存失败提示条、删除确认 | 只用于「操作失败、可能丢数据」；不要用在「字段没填」上 |
| 中性信息（说明性提示） | `#F4F1E6` | `#3A423B` | `#5C645C` | **9.18 : 1** | 说明「数据保存在本机浏览器」「参考区间仅供观察」 | 不要引入蓝色系 info 色 |

**三条不可破的语义规则**（来自产品文档第 8 节，视觉必须配合）：

1. **「未记录」不是警告。** 未填写的字段用行内文本 `--ink-4` 写「未记录」，不加底色、不加图标、不加边框。绝不能出现「无过敏」「0 次」这类由空白推断出来的结论。
2. **逾期不用琥珀。** 琥珀 = 「还没到期，记得去」。逾期改成**日期文字用 `#8E3A28`**，不加底色（加了底色整条待办就成了红条，压力太大，与「不要像交作业」的产品调性冲突）。
3. **存储降级用琥珀（warn），不是红。** 数据没丢，只是写到了浏览器缓存。红色会让人以为数据已毁。

### 1.6 纯白 `#FFFFFF` 用途白名单（只有四处）

1. 弹层 / 底部抽屉底（必须比所有下层更亮，才能「浮起来」）
2. 下拉面板、自动补全面板
3. 分段控件（segmented）的选中滑块
4. 报告原件缩略图 / 原件查看器的图底（要还原图片真实白）

其他任何地方用纯白都视为**违反规范**。这一条是为了让「哪里浮起来了」这件事在视觉上有唯一解读。

## 2. 字体与字号阶梯

### 2.1 字体栈（全部离线可用，不新增联网字体）

```css
--font-serif: 'Noto Serif SC','Source Han Serif SC','Songti SC',STSong,Georgia,serif;
--font-sans:  'Noto Sans SC','PingFang SC','Microsoft YaHei',system-ui,-apple-system,sans-serif;
--font-num:   'Inter','Segoe UI',Helvetica,Arial,sans-serif;
```

### 2.2 中文衬线（`--font-serif`）的使用范围

**只允许出现在这 5 个位置：**

1. 五个一级页面的 `h1` 页面标题（首页 / 就医记录 / 日常健康 / 健康主题 / 我的）
2. 记录详情页的 `h1`（就诊详情标题）
3. 区块标题 `h2`（「接下来要做」「最近记录」「关联报告」等）
4. 空态大标题（≤ 1 处/页）
5. 就诊摘要导出文档（`@media print` 的文档标题）

**明确禁止：**

- 正文、记录自由正文、摘要段落
- 表单 label、placeholder、帮助文本、错误提示
- 表格内容、chip、按钮、导航项、tabbar
- **所有数字**（含体重、血压、检验值、日期、编号）

**为什么数字不用衬线**：Noto Serif SC 的阿拉伯数字与 Inter 数字字面宽度不一致，`font-variant-numeric: tabular-nums` 在混排时会被破坏，表格数值列会跳。数字统一用 `--font-num` + `tabular-nums`，这是硬约束，不是审美偏好。

| `--fs-num` | 14 / 1.4 | 500 | num | 表格数值、日期块 | `tabular-nums` |
| `--fs-num-sm` | 12 / 1.4 | 500 | num | 时间戳、计数徽标 | `tabular-nums` |

**统一升级说明**：现状大量使用 10px / 10.5px / 11px / 11.5px / 12px 五种小字号，配合 `--muted-2`（2.8:1）形成「一片看不清的灰」。新版收敛为 12 / 13 / 14 / 15 / 18 / 26 六档，最小 12px。这是本轮视觉精修里性价比最高的一条。

### 2.4 中英混排与数字规则

1. **数字与中文之间留半角空格**：写「体重 62.4 kg」，不写「体重62.4kg」。空格写在文案里，**不要用 `letter-spacing` 模拟**（会把中文字距一起撑开）。
2. **不要给中文加 `letter-spacing`**。需要拉开字距的只有全大写拉丁（eyebrow / 表头英文），取值 `0.1em–0.14em`；中文超过 `0.02em` 就开始散架。
3. **所有数字容器加 `font-variant-numeric: tabular-nums`**：表格、日期块、统计值、时间戳、计数徽标。
4. **数值与单位不拆行**：`<span class="unit">mmHg</span>` 与数值同处一个 `white-space:nowrap` 容器。
5. **数值右对齐**，单位用 `--ink-4` 且比数值小一档（12px vs 14px 或 13px vs 26px）。
6. **正文最大行宽 34 个汉字**（约 620px / 68ch）。自由记录容器 `max-width:620px`，超宽屏不要拉到满屏。
7. **一级页面的眉标（eyebrow）保留但收紧**：按 027 的页头四槽位约定，`eyebrow` = 模块名的拉丁大写（`HOME` / `RECORDS` / `DAILY` / `THEMES` / `ME`），11px 500、`letter-spacing:.12em`、`--ink-4`，**桌面显示、手机隐藏**（省首屏高度）。不要用中文重复 H1 已经说过的话；辅助页写归属，如 `健康主题 · 检验指标`。

## 3. 间距与栅格

### 3.1 基准：4px

所有间距取 4 的倍数，**主节奏是 8**。实际只允许出现这 9 个值：

`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 64`

- 4px：图标与文字之间、chip 内 gap、label 与 input 之间（4–6px）
- 8px：同组元素间距、卡片间纵向 gap（紧凑列表）
- 12px：卡片间距、chip 之间、按钮之间、h2 与内容
- 16px：卡片内边距（手机）、栅格 gutter（手机）
- 20px：卡片内边距（桌面）、栅格 gutter（桌面）
- 24px：区块间距（手机）、页面左右 padding（平板）
- 32px：区块间距（桌面）、页面顶部 padding
- 40px：大区块之间（首页「快捷记录」与「接下来要做」之间可用 40）
- 64px：不用于间距，仅用于空态上下留白

**禁止**：13 / 14 / 15 / 18 / 22 / 26 / 30 这类「看起来差不多」的值。现状 CSS 里有 `gap:14px` `padding:13px` `margin:26px` 混用，是页面对不齐的主因。

### 3.2 栅格与容器

| 项 | 值 |
| --- | --- |
| 桌面内容最大宽度 | `1120px`（`main { max-width:1120px; margin:0 auto; }`） |
| 桌面栅格 | 12 列，gutter `20px`，左右 padding `32px` |
| 桌面常用组合 | 3 等分（快捷卡）、7:5（主列表 + 侧栏）、单列 `620px`（自由记录） |
| 平板（720–1023） | 内容流式，左右 padding `24px`，无 rail |
| 手机（<720） | 单列，左右 padding `16px`，栅格 4 列 gutter `16px` |
| 侧栏 rail 宽度 | `240px` 固定（≥1024 显示），内部左右 padding `16px` |
| 页面顶部 | 桌面 `padding-top:28px`，手机 `16px` |
| 页面底部 | 桌面 `48px`，手机 `calc(72px + env(safe-area-inset-bottom))`（与 027 §13.1 一致） |

### 3.3 手机端安全区

- `tabbar` 高度 `56px` + `padding-bottom: env(safe-area-inset-bottom)`
- `tabbar` 内每项最小命中高度 `56px`，宽度均分（390px 宽时约 78px）
- **`tabbar` 文字：12px / 1.2 / 500**（不是 11px）。图标 20 + 间距 3 + 一行 12px 文字，总高约 40，`56px` 装得下，没有理由压到 11px。
  选中 `--pine-700`，未选中 `--ink-4`（不是 `--ink-5`：未选中也要可读，5.92:1 vs 3.13:1）。**数量永远是 5 个**（027 §1.1），文字不换行、不缩写。
- 底部抽屉（sheet）：`padding-bottom: calc(20px + env(safe-area-inset-bottom))`，圆角只在上方 `16px`
- 固定定位的 toast：`bottom: calc(72px + env(safe-area-inset-bottom))`（避开 tabbar）
- `main` 底部 padding 必须大于 tabbar 总高 + 16px，否则最后一条记录会被遮

### 3.4 圆角

| token | 值 | 用于 |
| --- | --- | --- |
| `--r-xs` | `4px` | 内嵌小标签、代码片段 |
| `--r-sm` | `6px` | chip |
| `--r-md` | `8px` | 按钮、输入框、select、卡片内小容器 |
| `--r-lg` | `10px` | 图标容器、缩略图 |
| `--r-xl` | `12px` | 卡片、图标按钮 |
| `--r-2xl` | `16px` | 弹层、底部抽屉（上圆角） |

规则：圆角随尺寸递增，**不超过自身高度的一半**。禁止 `18px` / `20px` / `999px` 全圆 pill 混用（现状 chip 是 12px 全圆、按钮 9px、卡片 14px、弹层 18px，四种曲率无规律，是「模板感」的来源之一）。

## 4. 组件视觉规范

所有可点击元素：**全端命中区 ≥ 44×44**（视觉尺寸可以是 40，用 padding 或伪元素补足命中区）。焦点环统一 `outline: 2px solid var(--focus-ring); outline-offset: 2px;`（深色底上改用 `#A9BFAE`）。

### 4.1 快捷记录卡 `.quick-card`（首页三张主操作）

```
尺寸：桌面 grid 3 列，每卡 min-height 112，padding 18
      手机 单列，高 76
圆角：--r-xl (12px)
描边：1px solid var(--line)
底：  默认 --bg-card；「记一次就诊」--pine-050 底 + 1px var(--pine-100) 描边（弱强调）
栅格：display:flex; align-items:center; gap 12
  左：图标容器 40×40（--r-lg 10px，bg --pine-050，图标 20px stroke-width 1.7，色 --pine-500）
  右：.qc-body = **纵向两行**（flex-direction:column; gap 2; justify-content:center）
      · 标题 --fs-h3（15/1.5 600）--ink-1
      · 说明 --fs-cap（12/1.6）--ink-4，单行，最多 18 字
```
- **`.qc-body` 是纵向两行，不是标题和说明并排。** 76 的高度就是这么算出来的：`18(padding) + 40(内容) + 18 = 76`，而 40 = 标题 21 + gap 2 + 说明 21（取较大者）。并排的话内容只有 21 高，卡会塌成 57 或留下 19px 死白。
  实测对照（375 宽）：`.qc-title` top 176.5 / `.qc-desc` top 179.5 —— 同一行 = 错的；改对后 `.qc-desc` 的 top 应比 `.qc-title` 的 bottom 再低 2px。
- 说明**不加分隔符**（不写「记一次就诊 · 日期 + 一段记录」）。两行靠字号与颜色分层，不靠符号。
- 强调卡（记一次就诊）：底 `--pine-050`，描边 `--pine-100`，图标容器 `--pine-100`，图标 `--pine-600`，标题 `--ink-1`。**不是实底**（实底留给页头主按钮，见决策 3）。
- hover：默认卡 `border-color: var(--line-strong)` + `background:#FFFDF9`；强调卡 `background: var(--pine-100)`。**不做 translateY 位移**（三张卡一起跳会显得轻浮）。
- active：`transform: scale(.995)`，仅强调卡。
- focus-visible：`outline:2px solid var(--focus-ring); outline-offset:2px;`
- 禁用：不适用（快捷卡永远可点）。
- **禁止**：卡内超过两行文字、多色图标、渐变色底、右侧箭头。

### 4.1b 危急过敏提示条 `.allergy-alert`（首页，027 §3.1 第 2 块）

### 4.3b 区块标题与说明行 `.section-head`

所有区块标题共用一套规格；带说明的变体只加一行，不换样式：

```

  标题 h2：--fs-h2 18/1.4 600 serif --ink-2
```

### 4.4b 内层切换 `.chip-tab`（日常健康段内：体重 / 饮食 / 复盘，3 项）

与外层四段 `.seg` 刻意做成两种控件，避免「同一个页面里两个 segmented 打架」：

```
容器：display:flex; gap 8；无轨道底、无内边距（不套 pill 槽）

  未选中：透明底 + 1px solid var(--line)；文字 --ink-3
  选中：  bg --pine-100 + 1px solid var(--pine-100)；文字 --pine-700 600
  hover（未选中）：border --line-strong；文字 --ink-2
  focus-visible：outline 2px --focus-ring offset 1

```
- 层级关系：外层 `.seg`（4 段，带轨道）是「换模块」，内层 `.chip-tab`（3 个，无轨道）是「换视角」。**不叠加两层 segmented**——两层同形状控件会让人不知道自己点的是哪一层。
- 内层只有 3 项（体重 / 饮食 / 复盘），所以宽度不紧张，不需要横滑。
- 选中态用淡绿 `--pine-100` 而不是白色：白色滑块在上面已经有 `.seg` 用了，重复使用会失去层级暗示。

### 4.5 分段控件 `.seg`（就医筛选 全部/就诊/报告/用药；日常健康类型切换）

```

focus-visible：outline 2px --focus-ring offset 1

```

- 选中态**不用深绿实底**（会和主按钮抢）。白滑块 + 加粗字重已足够。
- 桌面端宽度随内容（不拉伸）；手机端四档等宽（每档 ≥ 44px 命中）。
- 语义按 027 §14.5 补 `role="tablist"` / `role="tab"` / `aria-selected`，样式层不用管。

```

```

**状态说明行 `.field-status`**（用于 027 §9 折叠 3：选中 ≥2 个文件后出现在文件选择器下方）

- 文案偏长（约 40 字）时允许 2 行，不需要折叠。
- 与 `.notice--warn` 的分工：这条讲的是**规则**（一直成立），warn 讲的是**当前状态需要注意**（这一次）。

- **一屏一个主按钮**。主按钮不出现在列表行里。

- 手机端表单底部主按钮 `width:100%`，次按钮在下方文字化。

## 5. 五页版式

通用骨架：`rail（240）+ main（max 1120）`；页面自上而下 = 页头（eyebrow + H1 + 说明 + 操作）→ 主内容区块。页头高度桌面约 76，手机约 96（含换行后的整行主按钮）。

> 本节所有区块顺序与 027（页面结构与交互规范）一致。视觉层只负责「谁最显眼、间距多少、单屏能看到什么」，不改变区块顺序与数量。

### 5.1 首页

**第一视觉焦点**：页头「记一笔」实底主按钮（全屏唯一的实底绿）。
**第二视觉焦点**：三张快捷卡（并列同级，其中「记一次就诊」用淡绿底弱强调）。
两者靠「小面积实底 vs 大面积淡色底」区分，不靠颜色深浅叠加。注意：第一焦点在页头、第二焦点在内容区，所以**页头必须紧跟三卡，中间不能插入任何其他区块**（过敏提示条除外，它是安全信息，允许插在中间并优先显示）。

**区块顺序（严格按此顺序渲染，与 027 §3.1 一一对应）**：
1. 页头：eyebrow `HOME` + H1「健康档案」+ `sub`（12px `--ink-4`）；右侧搜索框（宽 240）+ **实底主按钮「记一笔」**（`--on-pine` 文字）
2. 危急过敏提示条 `.allergy-alert`：无 critical 级过敏 → **整块不渲染**
3. 快捷记录：三卡一行（桌面）／三卡竖排（手机）；三张全部描边卡，「记一次就诊」为淡绿弱强调卡
4. 接下来要做：有内容才渲染；最多 3 条 `.todo-row`；标题右侧「全部 N 项」文字按钮；`openTodos().length === 0` → **整节不渲染**
5. 最近记录：3 条 `.rec-card--compact`；标题右侧「查看全部」；**空时只放一句引导文案，不放按钮**（放按钮会让「记一次就诊」在一屏出现三次，并把三张快捷卡挤出首屏）
6. 我关注的（可选）：最多 2 个卡片；未设置时整节不渲染
7. 页脚免责声明（沿用现有 `.disclaimer`，12/1.7 `--ink-4`）

**`.rec-card--compact` 与完整记录卡的差异**（首页精简版）：
- 摘要由 2 行改 **1 行** ellipsis
- 不显示右侧「更多」按钮，整卡为一个 `<a>`（027 §14.6）
- 日期左列宽 48（完整卡 56）
- 卡片高约 92（完整卡约 116）

**桌面首屏（1440×900，rail 240，main 1120）**：
`padding-top 28 + 页头 76 + 三卡 112 + 40 + 待办标题 28 + 3×48 + 32 + 最近标题 28 + 2×92 ≈ 780` → 首屏完整看到三卡 + 3 条待办 + 2 条最近记录。

**手机首屏（375×667，027 §3.4 的硬指标）**：
`页头（标题行 44 + 主按钮 44 + gap 8）96 + 三卡 3×76 + 2×12 = 252 + 区块间距 24` ≈ **372 → 三个快捷动作在 375×667 内完整可见，不折到第二屏**。剩余 295px 可容纳「接下来要做」标题 + 2 条待办。
注意：如果有 `.allergy-alert`（72px），三卡底边落在 444，仍在前屏内。

**禁止**：体重/BMI/减重目标大卡、完整度百分比、「健康评分」、渐变 hero、指标网格、六卡主题网格、同屏两个实底按钮。
**完整度的所有视觉变体都禁止**：百分比文字、环形进度、仪表盘、胶囊进度条、格子填色、「已填 X/14」出现在首页。这条对首页任何位置都成立（含侧栏、页头、区块标题右侧）。

### 5.2 就医记录

**第一视觉焦点**：时间线第一条记录卡的标题。

**顺序（对应 027 §4.1 的 7 块）**：
1. 页头：eyebrow `RECORDS` + H1「就医记录」+ sub「按日期排列的就诊、报告与用药」；右侧主按钮「记一次就诊」+ 次按钮「存一份报告」+ 搜索图标
2. 筛选条：四档 `.seg`（全部 / 就诊 / 报告 / 用药，各带条数）
3. 展开的筛选面板：搜索框 + 从/至日期 + 「清空筛选」；手机为 sheet
4. 结果摘要行：`共 N 条　就诊 X　报告 Y　用药 Z` —— **允许存在但必须弱化**：12px `--ink-4`、单行、不加底色、不加卡片、与上方筛选条间距 16、与下方列表间距 12。**禁止**把它做成统计条（大数字 + 分隔线 + 底色），那会让页面像工单后台。
5. 记录卡列表：**按年分组**（`2026 年　12 条`）；年下按事件日期倒序；「日期未确认」为独立分组，排在年分组**之前**，卡片日期位显示中性色「日期未确认」标签（`--st-todo-*`，虚线）
6. 分页：沿用 `pagerHTML()`，12px，居中，每页 20
7. 底部一行「检验指标趋势在「健康主题 → 检验指标」」+ 链接

**年分组标题样式**：12/1.4 600 `--ink-4` + 右侧条数 12 `--ink-5`（灰但不承载信息主体）+ 向右延伸 1px `--line-soft` 线到容器边缘；组间距 24，组内 `.rec-card` gap 8。

**桌面差异**：可选「表格视图」（`view=table`），表格列 = 日期 / 类型 / 标题 / 摘要 / 报告 / 来源 / 操作，操作列只放「更多」。默认仍是卡片列表。
**手机**：始终卡片（忽略 `view` 参数）；卡片全宽，无横向滚动；日期块与类型 chip 同一行。

**详情页顺序**（顶部返回 + 一行定位 `2026-11-01 · 门诊`，12px `--font-num` `--ink-4`）：
`就诊概况（H1 = 医院或「门诊记录」）→ 本次记录（15/1.85，max 620）→ 关联报告 → 本次用药 → 下一步安排 → 详细信息（折叠）→ 就诊摘要（折叠区内的入口）`

三处视觉细节：
- **关联报告**（区块标题已由「关联资料」改为「关联报告」，卡片统一用「报告」不用「资料」）：列表行 + 44×56 缩略图。若本次就诊只关联 1 份报告，用**单行卡**（高度约 72，缩略图 + 名称 + 日期 + 「查看原件」文字按钮），不要用「只有一条的列表」——一条列表会显得没做完。
- **下一步安排 / 同日提醒**：当同日有 ≥2 条就诊时，标题换为「同日提醒」并在下方加一行 `.section-note` 说明（规格见 4.3b），每条待办右侧带科室文本（见 4.10）。说明行是提示不是警告，用 `--ink-4`。
- **详细信息展开后**，字段间距 12，字段 label 13 `--ink-3` 与值 14 `--ink-2` 上下排列；空值统一「未记录」。

桌面：右上「导出给医生」次按钮；手机：底部 sticky 操作条（`导出给医生` 主按钮 + `编辑` 图标按钮），`padding-bottom: calc(12px + env(safe-area-inset-bottom))`。

### 5.3 日常健康

**第一视觉焦点**：顶部「今天记一笔」的输入条（不是图表）。

**顺序**：
1. 页头：eyebrow `DAILY` + H1「日常健康」；右侧 `.seg`（体重与饮食 / 体征 / 症状 / 睡眠）——**外层 4 段等宽**，手机为 H1 下方四档等宽（不横滑）
2. 段内切换：`.chip-tab` 3 项（体重 / 饮食 / 复盘）——**内层 3 个 chip，无轨道**，与外层 `.seg` 明确区分（规格见 4.4b）。切换内层不换页、不重排页头。
3. 今日记录条（卡片）：左侧「今天」+ 日期 12 `--ink-4`；中间 `input`（41.5，手机 16px 字号）或两个小输入（血压 116/74）；右侧主按钮「保存」——**这是本页唯一实底按钮**
4. 最近一次摘要：不超过 3 个 `.stat-cell`（值 `--fs-num-xl` 26/1.1 num 600 `--pine-700` + 标签 12 `--ink-4` + 变化说明 12 `--ink-4`）
5. 趋势图：卡片，高 240（手机 220，与 027 §13.8 一致）；标题 15/1.5 600 + 时间范围 `.chip-tab` 3 项（近 30 天 / 90 天 / 全部）；坐标轴文字 12 `--ink-4`；主系列 `--pine-500` 2px，参考区间带 `--pine-050`，异常点 `#8E3A28` 空心圆（`fill:#FDFBF6; stroke-width:2`）
6. 记录列表：`.row`，每行 = 日期 + 值 + 测量条件 + more

注意：本页会出现**两组**横向切换（外层 4 段 seg + 内层 3 chip），所以内层**必须**用无轨道的 chip 形态。若两者都做成 segmented，用户无法判断哪层是「换模块」、哪层是「换视角」。时间范围切换也用 3 chip，不用第三个 segmented（一屏最多一个 segmented）。

**禁止**：把四种类型的表单平铺在一屏；默认进入「体重与饮食」以外的类型（除记住上次使用）；图表放在今日记录之上。

### 5.4 健康主题

**第一视觉焦点**：主题卡网格里第一张卡的名称。

**顺序**：
1. 页头：eyebrow `THEMES` + H1「健康主题」+ 说明「你愿意长期跟的问题，不要求建档前先建」；右侧主按钮「新建主题」+ 次按钮「检验指标」

## 7. 深绿的使用纪律

**允许出现深绿（`--pine-700` / `--pine-600` / `--pine-500`）的 7 个位置，仅此 7 个：**

1. **主按钮底（全屏只允许 1 个）** —— 首页就是页头「记一笔」
2. 当前导航项的文字 + 图标（不是整块深绿底）
3. 关键数字（26px 档，每页 ≤ 3 个）
4. 链接与文字按钮（`--pine-600`）
5. 图标激活态、焦点环（`--pine-500`）
6. 图表主系列线（`--pine-500`）
7. 首页「记一次就诊」快捷卡的**图标与描边**（`--pine-600` / `--pine-100`）。**底色是淡绿 `--pine-050`，不是深绿** —— 它不是实底，不计入下面的按钮计数

**禁止**：
- 页面底、区块底、整块深绿卡（含首页快捷卡：它是淡绿，不是深绿，所以不构成例外）
- 表格行绿底、整行状态染色（用 chip 或 2px 色条代替）
- 图标多色 / 彩色图标 / 渐变图标
- 用深绿表示「成功」（成功用 toast + 「记录中」状态绿，语义分开）
- 用深绿表示「异常」（异常固定 `#8E3A28`）

**硬规则：任一屏内只允许 1 个实底深绿按钮。**（这是主规则，可逐屏数出来、可肉眼判定，比面积更好执行）
- 计数口径：`background: var(--pine-700)` 且面积 > 40×40 的元素。深绿 toast、深绿图标底不算。
- 若某屏出现 2 个，说明两个动作在抢同一个位置，回去改层级，不要靠「调浅一点」蒙混。
- 已知的唯一例外：`--pine-700` 的 toast 与主按钮同屏（toast 是瞬时层，不算竞争）。

**关于「面积」：不再设阈值。** 唯一实底是一个 40px 高的按钮，任何百分比阈值都没有适用对象，写出来只会和上面的硬规则互相解释不清。淡绿（`--pine-050` / `--pine-100` / `--pine-500`）同样不设比例上限，但一律不用于面积超过 1/3 屏的区块——这一条靠「看一眼是不是整块」判断，不需要算。

## 8. 无障碍与可用性硬指标

| 项 | 要求 | 自检方法 |
| --- | --- | --- |
| 正文对比度 | ≥ 4.5:1 | 本文所有「字/底」配对已实测，见 1.2 / 1.5 表；新增组合必须重算 |
| 大字（≥18px 或 ≥14px 600） | ≥ 3:1 | 同上 |
| 非文本对比（描边、图标、图表线） | ≥ 3:1 | 图标取 `--ink-3`（7.9:1）；`--line` 描边 1.3:1 **属于装饰性边界，不作为信息载体**，按钮和输入框必须用 `--line-strong` |
| 焦点可见 | 所有可交互元素有 2px outline + 2px offset | tab 遍历一遍，不能出现无焦点元素 |
| 点击目标 | **全端 ≥ 44×44**（与 027 §13.2 一致；视觉尺寸可 40，用 padding 或伪元素补足命中区） | 图标按钮、chip 旁按钮、more 按钮、待办勾选框最容易漏 |
| 状态不只靠颜色 | 状态 chip 必须带文字（「在服」「待复诊」），异常值必须带「↑/↓」符号 | 灰度截图自查 |
| 字号 | 正文 ≥ 14，小字 ≥ 12，输入框手机 16px | grep CSS 里的 `font-size:1[01]` |
| **色彩语义不得越级** | 三级固定：`--ink-4` 说明行 = **一直成立的规则/提示**（如「同名分组可能包含同一天其他就诊的提醒」）；琥珀 `.notice--warn` = **这一次需要注意**；`#8E3A28` = **错误或异常**。用错一级，用户就会以为出事了 | 逐条问：这句话是"永远成立的解释"还是"现在有问题"？前者绝不能上色 |
| **未记录 ≠ 异常** | 空白字段只用 `--ink-4` 写「未记录 / 未添加」，不加底色、图标、警示色；禁止从空白推断「无」「正常」「无过敏」 | 搜 `无过敏` / `均正常` / `未见异常` 应为 0 |
| 动效 | 仅 `opacity` / `transform`，时长 150–200ms；`prefers-reduced-motion` 下关闭 | 保留现有 reduce 规则 |

## 9. 实施前必读：明确「避免什么」

1. **不要**再用 `10px / 10.5px / 11.5px`（现状 37 处）。小字统一 12px。
2. **不要**再用 `--muted-2 (#8C9188)` 和 `--muted-3 (#A5AA9F)` 承载任何文字。这两个 token 直接从新的 CSS 里删掉，替换为 `--ink-4` / placeholder 专用 `--ink-5`。
3. **不要**给普通卡片加 `box-shadow`。阴影只给 `.modal` / `.dropdown` / `.toast`。
4. **不要**用 `#FFFFFF` 做卡片底。卡片 = `#FDFBF6`。
5. **不要**靠「把主色调浅一点」来解决两个动作抢位置的问题（见第 7 节：一屏只允许 1 个实底按钮，也不允许用两个淡绿底绕开）。
6. **不要**用全圆 pill 做 chip，不要用 18px/20px 这种无规律的圆角。
7. **不要**在页面顶部做通栏提示横幅；提示贴在使用它的动作旁。
8. **不要**用任何形式的「完整度」表达：百分比、环形进度、仪表盘、胶囊进度条、格子填色、「还有 N 项待补」、健康评分。首页、侧栏、页头都不出现。
9. **不要**给「未记录」加底色、图标或警示色，也不要把空白推断成「无」。
10. **不要**引入联网字体、图标字体、彩色插画。图标沿用 `js/app.core.js` 的 `I` 内联 SVG（`viewBox 0 0 24 24`，`fill:none`，`stroke:currentColor`，`stroke-width:1.7`，`linecap/linejoin:round`）。**5 个导航图标直接用现成的，无需新增**（与 027 §1.1 一致）：`grid`(首页) / `file`(就医记录) / `heart`(日常健康) / `check`(健康主题) / `user`(我的)。
11. **不要**在一屏出现两个实底主按钮（含「列表页页头主按钮 + 内容区主按钮」这种跨区块叠加）。
