## 1. 全局外壳与导航

### 1.1 五项一级导航

| key | 标签 | 侧栏图标 | 移动端标签（≤2 字） | 默认内容 |
| --- | --- | --- | --- | --- |

实现要点：
- `NAV` 收敛为上述 5 项，**删除 `group` 分组逻辑**（`buildNav()` 中的 `nav-group`/`nav-child` 分支不再需要）。
- `#tabbar` 渲染顺序即上表顺序，**删除 `data-act="more"` 的「更多」按钮**与 `openMore()`。
- 桌面侧栏：「我的」用 `margin-top:auto` 贴底（`rail-space` 保留在其上方）；桌面侧栏不常驻任何二级项。
- 侧栏底部只保留**一行**存储状态：`dot + 「数据已存本机库」/「浏览器存储模式」/「数据库写入失败」`，整行可点击 → `#/me`（滚动到「存储与帮助」）。**移除**原有「导出备份 / 个人资料 / 导入数据」三个按钮（备份与恢复统一进「我的」，与文档 §12「使用独立入口和明确名称」一致）。
- 计数徽标：不再挂在导航上（待办不是一级模块）。待办条数只出现在首页「接下来要做」右上的「全部 N 项」。
- 到期提醒红点 `[data-rdot]` 移除；改为首页「接下来要做」区块内逐条显示到期状态。

### 1.3 页头（复用 `setHead()`）

保留四槽位，语义收敛：

| 槽位 | 内容 | 规则 |
| --- | --- | --- |
| eyebrow | 模块名（小字大写间距） | 桌面显示；移动端隐藏（省首屏高度） |
| title | 日常语言页面标题 | 「健康档案」/「就医记录」/「日常健康」/「健康主题」/「我的」；详情页用记录本身的标题 |
| sub | 一句话现状或规则说明 | **不得**出现完整度百分比、待办数量、减重进度 |
| actions | 1 主 + 1 次 + 搜索 | 全站「每屏只有一个 `.btn-primary`（实底）」；搜索统一用 `data-act="search"`（复用 `openSearch()`） |

**首页实底归属（终稿 · 勿再翻转）**：首页**唯一实底主按钮 = 页头「记一笔」**（`--pine-700` 底 + `--on-pine` 字）；内容区三张快捷卡**全部描边、同级**，**没有「首页例外」**；「记一次就诊」只做淡绿弱强调（`--pine-050` 底 + `--pine-100` 描边），**不铺实底、也不能接近实底的浓度**。全屏只允许 1 个实底深绿按钮。

- **理由（决策记录）**：产品文档 §4 把三个动作**并列**列出（记一次就诊 / 存一份报告 / 记日常数据）。其中任何一个铺实底，等于替用户决定「先记就诊」；而「收到报告就存原件」是同等核心的场景。实底给页头的**通用入口**，三个动作卡保持同级。
- 硬规则替换：不再用「深绿面积 ≤ 视口 6%」这类面积阈值，改为更硬的**「全屏只允许 1 个实底按钮」**。
- 五个一级页统一：页头主按钮 = 实底；内容区的并列入口一律描边。
- 曾两次短暂改为「实底给快捷卡」，均作废，不要按旧稿实现。

移动端页头规则：
- `#pageActions` 换行到标题下一行，主按钮占满整行（`width:100%`），次操作降为文字按钮。
- 页头**不 sticky**；仅「就诊速记 / 报告采集」两个表单页用底部 sticky 保存条（见 §9.7）。

### 1.4 全局搜索

- 入口：`#pageActions` 的搜索图标；键盘 `/`（`app.boot.js` 已有监听，保留）。
- 覆盖范围（文档 §4）：自由记录正文、报告原件名称、医院、医生、药名、检验指标名与备注。

### 1.5 「弹层」还是「页面」——判定规则（全文统一）

实现方式（可编码）：

```js
const ALIAS = {
  overview:'/home', timeline:'/records', visits:'/records?t=visit', meds:'/records?t=med',
  issues:'/themes', todo:'/todos', profile:'/me',
  weight:'/daily?seg=body', diet:'/daily?seg=body&tab=diet',
  vitals:'/daily?seg=vitals', symptoms:'/daily?seg=symptoms', sleep:'/daily?seg=sleep'
};
function currentPage() {
  const raw = location.hash.replace(/^#\/?/, '');
  const key = raw.split('?')[0];
  if (ALIAS[key]) {
    const target = ALIAS[key];
    try { history.replaceState(null, '', '#' + target); }      // 静默改写地址栏，不新增历史
    catch (e) { /* file:// 下 replaceState 可能抛错：忽略，仅渲染目标页 */ }
    return parseHash(target).page;
  }
  return parseHash(raw).page || 'home';
}
```

- `replaceState` 不触发 `hashchange`，不会死循环；失败时降级为「渲染目标页但不改写地址栏」。
- 旧链接上的**任何查询参数一律丢弃**（旧路由本就没有 query），避免把脏参数带进新结构。

### 2.3 就诊详情的直达地址与「返回后保留筛选」

- 详情地址：`#/visit?id=v_xxx`。`id` 不存在 / 记录已删 → 渲染「这条记录不在了」+「回到就医记录」主按钮（不空白、不报错）。
- 打开详情时，列表把**当前筛选地址**带上：

```js
function detailHref(visitId) {
  const back = encodeURIComponent(location.hash || '#/records');
  return `#/visit?id=${encodeURIComponent(visitId)}&back=${back}`;
}
```

- 详情页「返回」按钮的行为优先级：
  1. 有 `back` 参数 → `location.hash = decodeURIComponent(back)`（刷新过、直达过来都能回去，且筛选条件还在）；
  2. 无 `back` 但 `history.length > 1` → `history.back()`；
  3. 否则 → `#/records`。
- 不在详情页顶部渲染「面包屑」，只用左上「← 就医记录」文字按钮（`aria-label="返回就医记录"`）。

### 2.4 状态存放原则（三档，必须严格区分）

| 状态 | 存放 | 理由 |
| --- | --- | --- |
| 就医记录筛选（`t/q/from/to/p`） | **URL 查询参数 = 唯一真源** | 需满足「进详情再返回保留筛选」；刷新、分享、手机从外部打开都要复原。实现成本仅一个 `readQuery()/writeQuery()` |
| 日常健康上次分段 | **`localStorage['personal-health-daily-seg-v1']`** | 属个人偏好，不具分享意义；不污染地址栏与历史。URL `?seg=` **显式出现时优先**（供旧链接与快捷入口） |
| 日常健康「体重与饮食」内层 tab | `localStorage['personal-health-daily-bodytab-v1']` | 同上 |
| 检验全部记录筛选（`q/cat/rep/range`） | **内存**（沿用 `ui.labAll`） | 该页筛选是临时查找行为，返回成本低；保持现状不改（减少改动面）。**例外**：若从该页进入某条详情再返回，需保留 → 用与 §2.3 相同的 `back` 参数，返回时按 `back` 重建内存态。**⚠ 本轮已知不一致**：`/records` 走 URL、`/labs-all` 走内存，两者刻意不同（见下方说明），不是遗漏 |
| 就诊速记草稿（未保存） | 内存 `ui.composerDraft`（本轮不做自动保存草稿，文档 §5「后续再考虑」） | 避免新增存储契约 |
| 保存成功的「刚刚新增」高亮 | 内存 `ui.flash = {kind:'visit', id}`，切换路由即清空 | 一次性提示，不入库 |

**为什么 `/records` 走 URL、`/labs-all` 走内存（本轮已知不一致，需保留注记）**

| 维度 | `#/records` | `#/labs-all` |
| --- | --- | --- |
| 用户是否会分享/收藏该筛选结果 | 会（「这是我 10 月的就诊」） | 基本不会 |
| 是否会被外部入口带参数打开 | 会（首页「查看全部记录」「全部待办」等会带 `t`） | 不会 |
| 现有实现 | 新写，无历史包袱 | 已有 `ui.labAll` + 分页 + 类别/报告联动，迁 URL 需重写并回归 |
| 本轮结论 | URL 唯一真源 | **保持内存 + `back` 参数**；后续若要统一，按 §18 第 6 条另开卡 |

> 后来人注意：这不是"忘了改"。两处筛选状态机制不同是有意取舍，改动前请先看本节与 §18 第 6 条。

**分段枚举（最终值，前后端与文档统一用这一套字符串）**

| 层级 | 参数 | 允许值 | 默认 | 中文标签 |
| --- | --- | --- | --- | --- |
| 外层四段 | `?seg=` | `body` \| `vitals` \| `symptoms` \| `sleep` | `body` | 体重与饮食 / 血压等体征 / 症状 / 睡眠 |
| `body` 段内层三项 | `?tab=` | `weight` \| `diet` \| `review` | `weight` | 体重 / 饮食 / 复盘 |

- 内层 tab **只在 `seg=body` 时有效**；`seg≠body` 时忽略并清除 `tab` 参数（避免脏参数留在地址栏）。
- 旧链接映射：`#/diet` → `#/daily?seg=body&tab=diet`；`#/weight` → `#/daily?seg=body&tab=weight`（等价于默认，可省略 `tab`）。
- **`seg` 不使用 `weight`/`diet`/`review`**，以免与外层四段混淆；`weight/diet/review` 是**内层**专有值。
- 校验函数（两端一致）：

```js
const SEGS = ['body', 'vitals', 'symptoms', 'sleep'];
const BODY_TABS = ['weight', 'diet', 'review'];
const LS_DAILY_SEG = 'personal-health-daily-seg-v1';
const LS_DAILY_BODYTAB = 'personal-health-daily-bodytab-v1';
function normalizeDailyQuery(seg, tab) {
  const s = SEGS.includes(seg) ? seg : 'body';
  const t = (s === 'body' && BODY_TABS.includes(tab)) ? tab : null;
  return { seg: s, tab: t };
}
```

URL 读写的可编码契约：

```js
const REC_DEFAULT = { t:'all', q:'', from:'', to:'', p:1, view:'card' };
function readRecordsQuery() {
  const qs = new URLSearchParams(location.hash.split('?')[1] || '');
  const out = { ...REC_DEFAULT };
  ['t','q','from','to','view'].forEach(k => { if (qs.get(k)) out[k] = qs.get(k); });
  out.p = Math.max(1, parseInt(qs.get('p'), 10) || 1);
  if (!['all','visit','report','med'].includes(out.t)) out.t = 'all';
  return out;
}
function writeRecordsQuery(next, { replace = false } = {}) {
  const qs = new URLSearchParams();
  Object.entries(next).forEach(([k, v]) => { if (v && v !== REC_DEFAULT[k]) qs.set(k, v); });
  const hash = '#/records' + (qs.toString() ? '?' + qs : '');
  if (replace) history.replaceState(null, '', hash);
  else location.hash = hash;              // push：浏览器返回可回到上一个筛选
}
```

- 切筛选 chip / 日期 / 翻页 → **push**（可后退）；
- 搜索框输入 → 300ms 防抖后 **replace**（不制造每键一条历史）。

```js
function nextUpTodos(n = 3) {
  const t = openTodos().slice();
  const today = todayISO();
  const rank = x => {
    if (x.flag) return 0;                                   // 主动置顶
    if (x.dueDate && x.dueDate < today) return 1;            // 已过期
    if (x.dueDate === today) return 2;                       // 今天
    if (x.dueDate) return 3;                                 // 未来：按日期升序
    return 4;                                                // 无日期：不显示逾期，排在最后
  };
  return t.sort((a, b) => rank(a) - rank(b)
    || (a.dueDate || '9999').localeCompare(b.dueDate || '9999')
    || (b.createdAt || 0) - (a.createdAt || 0)).slice(0, n);
}
```

- 勾选完成：行内即时变灰 + `toast('已标记完成')`，行保留 3 秒后从区块移除（保留可撤销窗口）；不做自动生成复查安排。

| 3 | **关联报告**（单数，不写「资料数量」） | `visit.reportId` → `reportById()`；`report.file` 原件；该报告下 `labs` | `未关联报告。` + `关联已有报告` / `存一份报告并关联` | 查看原件（`viewReport()`） | 替换关联 / 取消关联 |
| 3b | ↳ 未关联报告旁注（有才显示） | `reports` 中 `id !== visit.reportId` 的份数 | 无未关联报告时**整行不渲染** | 报告列表 → `#/records?t=report` | — |
| 4 | 本次用药 | `medications.filter(m => m.visitId === id)` | `本次就诊未添加用药。` + `记这次用药` / `关联已有用药` | 记这次用药（`openMedicationForm`，`visitId` 预填并锁定） | 编辑 / 取消关联 |
| 4b | 当前全部用药（**必须与 4 分开标注**） | `medications.filter(m => m.status === 'active')` | `没有状态为「在服」的用药。` | 查看全部用药 → `#/records?t=med` | — |
| 5 | 下一步安排 | `todoItems.filter(t => t.groupName === visitGroupName(v))` + `openTodos()` 中的未完成项 | `未添加下一步安排。` + `加复诊提醒` | 加复诊提醒（`openTodoForm`，`groupName` 预置 + 锁定） | 查看提醒 → `#/todos?visit={id}` |
| 6 | 详细信息（默认折叠） | `doctor`、`chief`（就诊原因）、`diagnosis`（明确诊断）、`note`（医嘱/备注） | 折叠摘要显示 `已填 2 项` 或 `未记录`；展开后每项未记录显示 `未记录` | 编辑（进编辑页并自动展开此区） | — |
| 7 | 就诊摘要 | `summaryDocHTML()` 复用 | 无依赖项时摘要内每节写「未记录」 | 预览并导出给医生（先预览，再打印/PDF） | — |

### 5.2 「本次用药 vs 当前全部用药」的强制文案

- 区块 4 标题：`本次就诊用药`，副文案：`这次就诊记录的药。药物可能跨多次就诊持续使用。`
- 区块 4b 标题：`当前全部用药`，副文案：**`在服药物不一定由这次就诊开具，记录就诊不会自动改变药物状态。`**
- 两处之间用 `divider` 分隔；区块 4 若为空，**不得**用「在服药物」填充（现有 `summaryMedsFor()` 已按 `visitId` 严格过滤，保持该口径）。

### 5.3 「关联报告」的现有模型事实与降级表达（本轮已拍板：不改数据模型）

- 事实：`visit` 只有**单个** `reportId` 字段；报告侧无 `visitId`；`report.file` 是原件路径。因此一次就诊**最多关联 1 份报告**，但该报告下可以有 N 项检验结果。
- **措辞硬规定**：就诊详情与摘要里**不出现**「资料数量」「N 份资料」等复数措辞；统一写「关联报告」，没有时写「未关联报告」。
- 详情表达：`关联报告　生化 2026-11-01 · 12 项结果`；旁注（仅当存在未关联报告时）：`报告列表里还有 3 份未关联`（纯文字，不写成「缺 3 份」）。
- **只有 1 份报告时用单行卡展示（约 72px 高），不要渲染成「只有一条的列表」**——一条的列表看起来像没做完，也会让用户以为还能加第二条。
- 已有 1 份时再点「关联已有报告」，弹确认：`这次就诊已关联《{旧标题}》。替换为《{新标题}》？原来那份仍会保留在报告列表里。`（取消即不改）
- 从速记表单一次选了多个文件时：**每份都建成报告记录（一份都不能丢）**，但只有第 1 份写入 `visit.reportId`。保存后提示必须同时说清两件事：
  `已保存 3 份报告。1 份已关联到本次就诊，其余 2 份已存入报告列表，可单独查看。`
  - 提示中的「查看报告列表」是可点文字 → `#/records?t=report`；
  - 不允许出现「其余 2 份未保存」或只提示成功却不提归属的表达。
- 详情页同名旁注的口径与速记提示一致：用「未关联」而不是「孤立」「多余」。
- **不得**按「同一天」自动关联任何报告或用药（文档 §6 明确禁止）。
- 多条关联（`reportIds[]` 或 `report.visitId`）**不在本轮范围**，见 §18 第 1 条与 §19。

### 5.4 待办的弱关联（本轮已拍板：`groupName` 方案 + 两条防误认约束）

- 事实：`todoItem` 字段仅 `{id, text, groupName, meta, flag, dueDate, followType, createdAt}`，**没有 `visitId`**。
- 约定：从就诊详情新建提醒时，`groupName` 由系统写为 `就诊 ${v.date}`（如 `就诊 2026-11-01`），`meta` 追加 `关联 ${科室 || '就诊'}`。详情页按 `groupName === 就诊 ${v.date}` 列出。
- **约束 ①（表单内只读）**：该分组字段在 `openTodoForm()` 中置为只读（`readonly` + 灰底），并在字段下方标注 `按就诊日期自动分组`。从「全部待办」页新增时，该字段才可编辑（保留 `datalist` 选择）。
- **约束 ②（同日多就诊不静默张冠李戴）**：当同一天存在 ≥2 条就诊记录时，详情页该区块标题改为 `同日提醒`，并在列表下方固定一行说明：
  `同名分组可能包含同一天其他就诊的提醒。`
  - 触发条件（可编码）：`visits.filter(x => x.date === v.date).length > 1`；
  - 此时每条待办右侧显示其 `meta` 中的科室文本，帮助用户自行区分；
  - 不因同日而合并、去重或隐藏任何一条提醒。
- 其余情况标题为 `下一步安排`。
- 已知限制（UI 必须写明，不隐藏）：手工改名后关联断开；同一天两次就诊共享分组。
- 若未来允许新增 `todoItem.visitId`，本节整段作废（见 §19）。

### 5.5 「未记录 / 未添加」的表达矩阵

| 位置 | 空的写法 | 禁止写法 |
| --- | --- | --- |
| 医院 / 科室 / 医生 | 该行不渲染 | `无`、`—` 单独出现 |
| 自由记录 | `本次没有写记录。` + 补充按钮 | `无内容` |
| 关联报告 | `未关联报告。` + 关联/添加按钮 | `未添加资料`、`无资料`、`无附件`、`资料 0 份` |
| 本次用药 | `本次就诊未添加用药。` | `无用药` |
| 下一步安排 | `未添加下一步安排。` | `无需复诊`、`无安排` |

## 6. 日常健康 `#/daily?seg=`

### 6.1 分段与记住上次选择

**枚举以 §2.4「分段枚举（最终值）」为唯一权威**，本节只说明行为，不重复声明常量。

| seg key | 标签 | 主按钮 | 渲染来源（复用） |
| --- | --- | --- | --- |
| `body` | 体重与饮食 | 记录体重 / 记录今天 | `slImWeightHTML()/slImDietHTML()/slImWeekHTML()`（**去掉 `slImOverviewHTML()`，「概览」不再出现**） |
| `vitals` | 血压等体征 | 记录体征 | `renderVitals()` |
| `symptoms` | 症状 | 记录症状 | `renderSymptoms()` |
| `sleep` | 睡眠 | 记录睡眠 | `renderSleep()` |

`body` 段内层三项（`?tab=`）：

| tab key | 标签 | 渲染 | 说明 |
| --- | --- | --- | --- |
| `weight` | 体重 | `slImWeightHTML()` + 体重/体成分图表 | 默认项 |
| `diet` | 饮食 | `slImDietHTML()` | 旧 `#/diet` 落这里 |
| `review` | 复盘 | `slImWeekHTML()` | — |

- 「概览」段**删除**：它的内容（当前体重、7 日摄入、进度）已分别落在首页摘要与 `weight`/`diet` 段，保留会造成两处「概览」。
- 内层 tab 在 `seg≠body` 时不渲染，且地址栏不保留 `tab` 参数（见 §2.4 `normalizeDailyQuery()`）。
- **控件形态必须区分层级（避免用户分不清在点哪一层）**：外层 4 段用分段控件（有轨道），内层 3 项与图表时间范围用**无轨道 chip**；并且**一屏最多只出现 1 个分段控件**。若将来需要第三层切换，一律用 chip，不得再加第二个 segmented。

分段取值优先级（可编码，常量见 §2.4）：

```js
function currentDailySeg() {
  const qs = new URLSearchParams(location.hash.split('?')[1] || '');
  const fromUrl = qs.get('seg');
  if (SEGS.includes(fromUrl)) return fromUrl;                       // ① URL 显式优先（旧链接/快捷入口）
  const saved = localStorage.getItem(LS_DAILY_SEG);                 // ② 上次选择
  return SEGS.includes(saved) ? saved : 'body';                     // ③ 初次：体重与饮食
}
function setDailySeg(seg) {
  if (!SEGS.includes(seg)) return;
  try { localStorage.setItem(LS_DAILY_SEG, seg); } catch (e) {}
  const qs = new URLSearchParams(location.hash.split('?')[1] || '');
  qs.set('seg', seg);
  if (seg !== 'body') qs.delete('tab');          // 内层 tab 只在 body 段有效
  history.replaceState(null, '', '#/daily?' + qs);  // 不新增历史，避免「返回」退回上一个分段
  route();
}
function setBodyTab(tab) {
  if (!BODY_TABS.includes(tab)) return;
  try { localStorage.setItem(LS_DAILY_BODYTAB, tab); } catch (e) {}
  const qs = new URLSearchParams(location.hash.split('?')[1] || '');
  qs.set('seg', 'body'); qs.set('tab', tab);
  history.replaceState(null, '', '#/daily?' + qs);
  route();
}
```
- **存哪**：`localStorage`，键名 `personal-health-daily-seg-v1` 与 `personal-health-daily-bodytab-v1`（沿用现有 `personal-health-*-v1` 命名族）。
- 记忆失败（隐私模式/配额满）不报错，退化为「每次进入回到体重与饮食 / 体重 tab」。

### 6.2 分段内布局顺序（四段统一，便于一致心智）

| # | 区块 | 内容 | 空数据时 |
| --- | --- | --- | --- |
| 1 | 分段切换条 | 4 个等宽 chip（移动端一行 4 等分，**不横向滚动**；<360px 时 2×2） | — |
| 2 | 最近一条摘要 | `最近记录 2026-11-01 · 71.2 kg · 比上次 −0.3 kg`；无症状时 `还没有记录` | 显示 `还没有记录。` + 主按钮 |
| 3 | 趋势图 | `echartsChart()`；单指标下拉（体征段）或固定指标（体重段） | **不渲染空图**，改为 `emptyGuide()`：`记下第一次之后，这里会画出趋势。` |
| 4 | 记录列表 | 桌面 `.data` 表格；移动端卡片；分页 `paginate()` | 显示一行 `还没有记录。` + 主按钮（不重复大引导卡） |
| 5 | 说明（折叠） | 参考区间、称重规则、`数据用于个人整理，不能替代医生解读` | 始终可展开 |

顺序理由：先给「我现在怎么样」（摘要），再给「趋势」，记录动作的主按钮固定在该页页头 actions，列表放最后（找旧记录是低频动作）。

### 6.3 各段默认字段（与文档 §9 一致，不改现有表）

| 段 | 默认只展示 | 按需补充（折叠） |
| --- | --- | --- |
| 体重与饮食 | 日期（默认今天）、体重、测量条件 | 体脂/围度/肌肉量等（现有 `WEIGHT_METRICS`）、备注；饮食按餐另记 |

| 症状 | 日期、哪里不舒服 / 一句描述 | 程度、诱因、照片、主题 |
| 睡眠 | 最近睡眠记录 + 设备导入入口 | 入睡、起床、主观感受 |

## 7. 健康主题 `#/themes` + `#/theme?id=`

### 7.1 列表页区块顺序

| # | 区块 | 内容 |
| --- | --- | --- |
| 1 | 页头 | title `健康主题`；sub `长期回看某个问题：相关的就诊、报告、症状和计划`；actions：主按钮「新建主题」（见 §7.5 能力说明） |
| 2 | **检验指标入口卡（固定第 1 位）** | 标题 `检验指标`；副文案 `按指标看趋势，或查看全部检验结果`；两个动作：`趋势` → `#/labs`、`全部记录` → `#/labs-all` |
| 3 | 主题卡列表 | 每卡：`名称` + `状态 chip`（记录中/待随访/监测中/历史记录/待补充/仅目录）+ `最近记录 2026-08-19 · CT 平扫` + `一句摘要` + `关联 就诊 3 · 报告 2 · 症状 1`；整卡点击 → 主题详情 |
| 4 | 空态 | `还没有主题。主题用来长期回看某个问题，第一次记录时不用先建。` + 主按钮（新建/去记录） |

**检验指标为什么放在这里**（需在文档中说明，防止后续被挪走）：
1. 检验指标本质是「按指标长期回看」，与主题的心智一致；单独立一级会让一级导航变 6 项，违背「五项固定」。
2. 指标不属于某个具体疾病主题（同一份生化会牵涉多个主题），所以不能塞进某个主题详情，只能作为**横切入口**固定在列表首位。
3. 它是「查看」而非「录入」入口，位置稳定在首位、不参与列表排序，因此不会被主题排序影响。
4. 现有 `#/labs`、`#/labs-all` 路由与实现完整，保留路由只改高亮，改动成本最低。

- 状态/备注编辑：`data-act="issue-edit"`（保留现有弹层）。
- 返回：`back` 参数同 §2.3。

- 保留现有实现与信息层级（趋势图 + 最近录入 + 指标清单 + 报告原件 + 备份），但：
  - 页头 eyebrow 改为 `健康主题 · 检验指标`；高亮健康主题。

  - 「报告原件」卡保留（它是指标来源的追溯，属查阅而非备份）。
  - 移动端图表高度 220（现有逻辑已按 `window.innerWidth < 700` 处理），并给出 `role="img"` + 文字摘要（见 §15）。

## 8. 我的 `#/me`

### 8.1 四分区（顺序固定）

| # | 分区 | 内容 | 主要动作 | 命名要求 |
| --- | --- | --- | --- | --- |
| 1 | 个人信息 | 基础资料（`profileFields()`：姓名/出生/身高/…）、**重要过敏信息**（`historySectionsHTML()` 的过敏块置顶并高亮 critical）、相关既往史（家族史、手术/住院史）、当前在服用药（只读摘要 + 链接） | 编辑资料（弹层） | 分区标题 `个人信息` |

### 9.5 最低保存条件的判定（伪代码，必须照此实现）

```js
/* 文档 §5.3：有效日期 + （非空自由记录 | 至少一份附件 | 就诊原因/诊断/医嘱 至少一项）
   只选日期不生成空记录；仅「关联了一份已有报告」不算内容（那是引用，不是本次记录）。 */
function canSaveVisit(f) {
  const dateOK = /^\d{4}-\d{2}-\d{2}$/.test(f.date) && !Number.isNaN(Date.parse(f.date + 'T00:00:00'));
  if (!dateOK) return { ok: false, reason: 'date' };

  const textOK = String(f.summary || '').trim().length > 0;
  const attachOK = (f.attachments || []).filter(a => a.saved && (a.file || a.fileId)).length > 0;
  const proOK = ['chief', 'diagnosis', 'note'].some(k => String(f[k] || '').trim().length > 0);

  if (textOK || attachOK || proOK) return { ok: true };
  return { ok: false, reason: 'empty' };
}

/* 保存按钮状态机 */
const state = canSaveVisit(draft);
saveBtn.disabled = !state.ok;
saveBtn.title = state.ok ? '' : (state.reason === 'date' ? '请先选择就诊日期' : '再写一句记录，或添加一份报告');
// 说明：disabled 只用于视觉弱化；键盘用户点按 disabled 无法获知原因 → 改为 aria-disabled="true" + 点击时在按钮上方显示提示行
```

按钮可用性表达（重要，勿用 `disabled` 静默拦截）：
- 保存按钮始终可点（`aria-disabled="true"` 时视觉弱化）。
- 点击且 `reason==='date'` → 焦点移到日期输入 + 错误行 `请先选择就诊日期`；
- `reason==='empty'` → 焦点移到自由记录 + 错误行 `写一句就能保存；也可以先加一份报告。`

### 9.6 保存成功

| 步骤 | 行为 |
| --- | --- |
| 1 | 先建报告、再写就诊，最后写 `reportId`：**顺序不能反**（保证多文件时"一份都不丢"）。逐份 `persistReports()`，任一份失败 → 走 §9.7，全部回滚并保留 draft |
| 2 | `persistHistory()` 写就诊记录，**确认写入成功**（`syncBad` 为假）后才继续 |
| 3 | 设置 `ui.flash = { kind: 'visit', id }` |
| 4 | `location.hash = from || '#/home'`（回到发起页） |
| 5 | `toast` 文案按关联份数分两种（**必须区分，不能只说"已保存"就吞掉归属**）：<br>· 1 份或 0 份：`已保存`<br>· ≥2 份：`已保存 3 份报告。1 份已关联到本次就诊，其余 2 份已存入报告列表，可单独查看。` |
| 6 | 发起页渲染时，若 `ui.flash` 命中某条记录 → 该卡加 `.is-flash` 描边 2s，并在列表顶部插入一行 `已保存 · 查看这条记录 →`（点击进详情）；离开该页清除 `ui.flash` |
| 7 | 若本次产生 ≥2 份报告，临时行追加可点文字 `查看报告列表（+2）` → `#/records?t=report` |
| 8 | **不**连续弹出「加复诊提醒 / 记这次用药」的强制流程；详情页内提供这两个次要按钮即可 |
| 9 | 不显示「稍后整理」「待完善」等标签（速记是正式记录） |

### 9.7 保存失败

- 条件：写库抛错 / `syncBad` 为真 / `storeMode==='local'` 且 localStorage 写入异常。
- 必须：页头不关闭、输入全保留、已选附件保留、折叠区展开状态保留、**不显示「已保存」**。
- 错误条位置：保存按钮**正上方**，`role="alert"`，文案必须同时给出原因与下一步：
  - 服务模式失败：`没保存成功。检查「启动健康档案.bat」窗口是否有报错，然后点「重试保存」。`
  - 降级模式：`没存进本机数据库。现在能存到浏览器，但换设备会丢。`
- 提供「重试保存」（重新提交同一 draft）与「复制这段文字」（把自由记录复制到剪贴板，防止丢内容）。

### 9.8 离开有未保存内容

判定 `dirty`：`draft` 与初始快照 `initial` 逐字段比较（`summary`、`date`、折叠区字段、`attachments`、`reportId`），任一不同即为 dirty。

```js
function guardLeave(nextHash) {
  if (!isDirty()) { location.hash = nextHash; return; }
  openModal(`<div class="modal-head"><h2>这次记录还没保存</h2></div>
    <p>离开会丢掉刚写的内容。</p>
    <div class="form-actions">
      <button class="btn btn-primary" data-act="stay">继续填写</button>
      <button class="btn btn-ghost btn-danger" data-act="discard" data-to="${esc(nextHash)}">放弃本次内容</button>
    </div>`);
  // 「继续填写」= 关闭弹层，把 hash 回滚到当前表单地址：
  //   由于点导航已改了 hash，需 history.replaceState(null,'', 表单地址) 复原，不再触发 hashchange
  // 「放弃本次内容」= 清空 draft → location.hash = nextHash
}
window.addEventListener('beforeunload', e => { if (isDirty()) { e.preventDefault(); e.returnValue = ''; } });
```
拦截范围：① 侧栏/底部导航点击（`data-act="go"` 分支）②「← 取消」③ 浏览器刷新/关闭。**不**拦截：折叠区展开/收起（不算数据变更）。

### 9.9 编辑已有记录：折叠区不得清空已有值

规则（三条，必须同时成立）：
1. **初值即全量**：表单初始值为 `normVisit(rec)` 的**全部**字段，无论折叠区是否展开。
2. **收起 ≠ 清空**：折叠内容用 `hidden` 属性或 CSS 隐藏，**不使用** `disabled`、不销毁 DOM、不重置 input；提交时按 FormData 读取。
3. **未展开区块不产生空串**：保存时对折叠区字段做「`undefined` 沿用旧值，`''` 才算用户清空」的合并。

```js
function mergeVisitForm(prev, draft) {
  const prevV = prev || {};
  const pick = (k) => (draft[k] === undefined ? (prevV[k] ?? '') : draft[k]);
  return normVisit({
    id: prev ? prev.id : newId('vis'),
    date: draft.date,                                  // 必填，必来自表单
    visitType: pick('visitType') || prevV.visitType || '门诊',
    department: pick('department'), hospital: pick('hospital'), doctor: pick('doctor'),
    chief: pick('chief'), diagnosis: pick('diagnosis'),
    summary: draft.summary === undefined ? (prevV.summary || '') : draft.summary,
    note: pick('note'),
    reportId: draft.reportId === undefined ? (prevV.reportId || '') : draft.reportId,
    createdAt: prevV.createdAt || Date.now()
  });
}
```

- 用户显式清空（把输入框内容删光）→ 视为清空，保存后为空。为防止误清空，清空非空字段时给一次轻提示：`已清空「医院」，保存后这项会变成未记录。`（不阻断保存）。
- **旧「就诊小结」→ 自由记录初始内容**：编辑已有记录时，自由记录初值 = `prev.summary`；即使 `summary` 为空但 `chief/diagnosis` 有值，**也不**把它们拼进自由记录（各字段保留原义）。折叠区照常显示原值。
- 保存速记**不得**覆盖：原有关联报告（`reportId`）、关联用药（`medication.visitId` 由他表持有，本表单不触碰）、旧 `createdAt`。
- 旧记录仍可查看（文档 §5）：`normVisit` 允许 `summary` 为空、只靠 `chief`/`diagnosis` 的老记录 → 按新规则**不阻止保存**（`canSaveVisit` 的 `proOK` 覆盖），不得借新规则删除历史内容。

### 14.1 焦点环的唯一正确写法（可直接抄）

```css
/* ❌ 禁止：键盘用户从此完全没有焦点提示 */
.x:focus { outline: none; }

/* ❌ 禁止：低 alpha 光晕冒充焦点环，实测 .08 → 1.1:1、.16 → 1.24:1，等于没有 */
.x:focus { outline: none; box-shadow: 0 0 0 3px rgba(47,107,87,.16); }

/* ✅ 全站唯一写法 */
.x:focus-visible { outline: 2px solid var(--focus-ring); outline-offset: 2px; }

/* ✅ 只想"鼠标点不显示、键盘走显示"时，用反向选择器表达，不要动 :focus */
.x:focus:not(:focus-visible) { outline: none; }

/* ✅ 深色实底（深绿按钮）上换环色，否则环与底同亮度 */
.btn-primary:focus-visible { outline: 2px solid var(--focus-ring-on-dark); }
```

判定三句话：

1. **`:focus` 选择器上永远不出现 `outline:none`** —— 要表达「鼠标态关掉」只能写 `:focus:not(:focus-visible)`。
2. **焦点环必须是不透明实色 outline**，`outline-offset` 固定 `2px`。`--pine-100`（`#E7EFE8`）**不能**当焦点环：对纸底 1.00:1、对卡片底 1.13:1，不透明也照样看不见——它「看起来内嵌」只是因为它跟背景同色，不是因为够对比。
3. **深色底换 `--focus-ring-on-dark`**（`#A9BFAE`，对 `--pine-700` 5.99:1）。`--focus-ring` 在深绿上只有约 1.5:1。

> 同一条也适用于 `@media print` 之外的所有交互控件；错误态字段获得焦点时允许把环色换成 `#8E3A28`（错误优先级高于通用焦点色），但**不能取消环**。

## 17. 数据流不变量（实现时不得破坏）

1. `visit` / `medication` / `report` / `lab` / `weight(body)` / `vital` / `symptom` / `sleepLog` / `todoItem` 各自独立，**页面聚合 ≠ 数据合并**。
2. 权威关联只有两个外键：`visit.reportId`（单值）、`medication.visitId`（可空）。不得以「同一天」自动建立任何关联。
3. `visit.summary` 承载自由记录正文；`chief`（就诊原因）、`diagnosis`（明确诊断）、`note`（医嘱/备注）各自保留原义，互不填充、互不推断。
4. 药物 `status` 只由用户修改；记录/编辑就诊**不改变**任何药物状态。
5. 未记录一律未知：不补 `0`、不补「正常」、不补「无」。
6. 时间线是只读聚合视图，不建表、不让用户另填一条「时间线」。
7. `ARCHIVE.timeline` 中的静态历史事件**只读**呈现，标注来源，不参与编辑与删除。

| B | 别名**指向旧的低对比度值**（如 `--muted-3` 仍指向 `#A5AA9F`） | **当场改**，不得记入待清理 | **P1 阻塞** |
| C | 别名存在但**全站无任何引用**（死代码） | 直接删除 | 不计入 |

- B 档最危险：等于以「兼容」的名义把 2.07:1 合法化，且走查会误判为通过。判定时必须**把变量链解析到字面值**（`--a: var(--b)` → 查 `--b` 的最终 hex），再用该 hex 重算对比度，不能只看声明行。
- **规模实测（2026-11-01，改动前基线）**：`js/*.js` 中有 **99 处**内联旧 token 引用——`app.views.body.js` 74、`app.views.profile.js` 11、`app.views.health.js` 8、`app.chart.js` 3、`app.modal.js` 2、`app.boot.js` 1；按变量分：`--muted-3` 54、`--muted-2` 19、`--muted` 14、`--line-2` 6、`--warn` 3、`--line-3` 3。
  这个规模决定了一件事：**「留别名」会是默认结局，而不是例外**。因此必须明确两种收场都不可接受：
  - **不留别名** → `color:var(--muted-3)` 成为非法值，浏览器按继承处理，次要文字变近黑，层级静默垮掉（不报错、不警告）；
  - **留别名指向旧值** → 54 处继续跑 2.07:1，正好命中 B 档。
  → 结论：正确做法是**逐处按语义替换成新 token**，别名只作过渡且不得指向旧值。
- **时间约束**：兼容别名**只允许活到第二批结束**。第二批（日常健康 / 健康主题 / 我的）交付时，以下 12 个旧名必须全部从样式与代码中删除，且不得再被引用：
  `--paper-2`、`--card`、`--muted`、`--muted-2`、`--muted-3`、`--line-2`、`--line-3`、`--warn-bg`、`--amber-bg`、`--green-bg`、`--mute-bg`、`--shadow`
- **判定轴：旧名删、新名留（一个都不能删）**。以下为新色板保留项，任何情况下不得列入删除范围：
  `--on-pine`、`--on-pine-2`、`--pine-050`、`--pine-100`、`--pine-500`、`--pine-600`、`--pine-700`、`--pine-900`、`--ink-1`~`--ink-5`、`--line`、`--line-soft`、`--line-strong`、`--fs-*`、`--sp-*`、`--r-*`。
  > 注意 `--line-2` / `--line-3` 属**旧名**要删，`--line` / `--line-soft` / `--line-strong` 属**新名**要留——三者只差一个后缀，最容易批量替换时误删，执行时逐条核对不要用通配。
- **判定轴（迁移完成度防虚高）：同一选择器在同一个样式表里出现 ≥2 次时，必须确认旧的那条被物理删除，而不是靠后出现的新规则覆盖。**
  这一条与上面的 `sed` 禁令互补：`sed` 禁令防的是「替换事故」，本条防的是「旧规则没删、靠新规则覆盖、结果没覆盖住」——它不会报错、不会掉色，截图完全正常，但旧值仍然在某个状态下生效。
  本期已实测到 **6 组**重复，全部按本条处理：

  | 选择器 | 旧（必须删） | 新（保留） | 谁在生效 |
  | --- | --- | --- | --- |
  | `.card` | 264 行 | 1216 行 | 同特异性，后者胜——属**侥幸通过**，仍要求物理删除旧条 |
  | `.field` | 623 行 | 1356 行 | 同上 |
  | `.hint` | 637 行（`10px` + `--muted-3`） | 1228 行（`--fs-cap` + `--ink-4`） | 同上 |
  | `:focus-visible` | **110 行**（`outline:2px solid var(--pine-2)`） | 1126 行（`var(--focus-ring)`） | 两条声明的三个属性（`outline` / `outline-offset` / `border-radius`）完全重合，后者全胜 → 110 行是**纯死声明**，不产生视觉效果但会误导「迁移已完成」的判断，第一批随焦点环一并删除 |
  | `::placeholder` | **227 行**（`.search input::placeholder{color:#A8ADA2}`）<br>**636 行**（`.field input::placeholder{color:#B3B7AC}`） | 1127 行（`::placeholder{color:var(--ink-5)}`） | **旧条特异性更高（0,1,2 > 0,0,1），新条没覆盖住**，硬编码色仍在生效（1.97:1）。与 `.field input:focus` 同属 P1 |
  | `.field input:focus` | **633 行**（`rgba(...,.08)`，特异性 **0,2,1**） | 1126 行 `:focus-visible`（特异性 **0,1,0**） | **旧条特异性更高，新条根本没覆盖住**——属 P1 |

  判定动作：对任一被迁移的选择器，`grep -c "选择器{"` 必须为 1；为 2 时先删旧条再谈迁移完成。
- **基线实测（2026-11-01）**：`styles.css:69–93` 现存 **25 个兼容别名**，**逐个解析后全部指向新值**（如 `--muted-3: var(--ink-4)`、`--line-2: var(--line-soft)`、`--pine-2: var(--pine-500)`）——即**当前 B 档为 0 个**，P1「以兼容名义合法化 2.07:1」的风险尚未实际发生。
  这有两层含义：① 现在那 54 处 `var(--muted-3)` **渲染出来是对比度合格的**（这正是截图看不出问题的原因，别因为「看着还行」就判定 token 迁移完成）；② 真正的 P1 风险不在别名定义，而在**第二批删别名时的连带失效**——别名一删，未替换的引用立刻变非法值。所以本批只做「不许新增旧名引用 + 物理删除重复旧规则」，替换留给第二批，与已拍板口径一致。
- 走查不把「别名存在」本身当作不通过依据；只有当它命中 B 档、或超过上述时间点仍存在时才计缺陷。
- 同一口径适用于渲染代码里的旧 class 名（如旧 `.storage`/`.band`）残留：**有引用即算在用，必须删干净**，理由同上（视觉正常 ≠ 代码正确）。
- **旧名 → 新名映射（替换时必须按语义逐条替换，禁止通配/sed 批量）**：

  | 旧名 | 新名 | 说明 |
  | --- | --- | --- |
  | `--muted-3` | `--ink-4` | 共 54 处，最集中的一处；旧值 2.07:1 |
  | `--muted-2` | `--ink-3` | 19 处 |
  | `--muted` | `--ink-2` | 14 处 |
  | `--line-2` | `--line` | 6 处（容器描边） |
  | `--line-3` | `--line-soft` | 3 处（行分隔/弱描边） |
  | `--warn` / `--amber` | 异常色 `#8E3A28` 或对应语义 token | 3 处，需逐处判断是"错误"还是"需注意" |

  > **严禁 `sed 's/--line/xxx/'`**：会把 `--line-strong` 截断误伤；`--line-2`→`--line`、`--line-3`→`--line-soft` 必须按完整名匹配。同理 `--muted` 是 `--muted-2`/`--muted-3` 的前缀，按子串替换会连环改坏。
- **增量要求（本批走查即适用）**：新增/改动的渲染代码不得引入旧 token；`js/app.chart.js` 额外按 §21 处理（canvas 拿不到 CSS 变量）。

## 21. 图表色源：canvas 不走 CSS 变量（实现契约）

**问题**：ECharts 画在 canvas 上，**读不到 CSS 变量**，所以 `app.chart.js` 里是一批硬编码 hex。实测 19 处引用、15 个不同色值。**改色板时这些不会跟着变，且截图看起来"还是绿的"，视觉走查极易放过。**

先分清哪些是旧的、哪些是**当前正确的**——这一步不做，批量替换会把对的改错：

| 分类 | 色值 | 判定 |
| --- | --- | --- |
| **当前值，保留** | `#2F6B57`（×2，= `--pine-500`）、`#173F33`（= `--pine-700`） | 与新色板一致，**不得替换** |
| 旧值，待换 | `#1B1E1B`（旧 ink）、`#A5AA9F`（旧最浅次要文字，2.07:1）、`#A9752F`（旧琥珀）、`#B4553F`、`#E2DDD0`（旧描边）、`#4A5248`、`#8C9188`、`#F0EBE0`、`#B9CDBD` | 换为新 token 对应值 |
| 中性/需逐处判断 | `#fff`、`#8A5B7A`、`#6B8A5B`、`#5B7DA8`（多系列区分色） | 不得按「旧值」批量替换；先确认是否承担"区分系列"职责 |

> 教训：我先前把 `#173F33` 判成「旧深绿」，实际它就是当前的 `--pine-700`。**判「旧」必须回到 `:root` 逐个比对字面值**，不能凭观感。

**契约**：
1. `app.chart.js` 顶部**只读一次** `getComputedStyle(document.documentElement)`，把需要的 token 缓存成模块级常量；禁止在 series 配置里散落 hex。
2. 缓存必须在**主题/模式变化时失效重取**（本项目当前只有一种模式，但接口要留出口，避免以后加暗色时静默用错色）。
3. 图表用色只能来自新色板：主系列 `--pine-500`、异常 `#8E3A28`、网格线 `--line-soft`、文字 `--ink-4`、tooltip 底 `--paper` 等；**不得**再出现上述旧值。
4. 同一份契约适用于 `@media print`（就诊摘要/打印导出）——打印是另一套色源，不跟主题走，必须单独核对。
5. 走查判定：`grep -oE "#[0-9a-fA-F]{3,8}" js/app.chart.js` 应只命中「注释/映射表」，不应命中 series 配置体内的字面色。

> 说明：具体色值以 026 为准，本节只约束"色从哪来"。canvas 色源与内联 `style="color:..."` 是两处最容易被截图漏掉的盲区。
