# 设计文档：检验指标标准化与单位/方法换算

> 状态：**已定稿（v2）** — 用户确认 A（自建字典+LOINC可选）/ B（国内常用基准单位）/ C（提示但画标准值线）/ D（做未映射清单）。开始实现。
> 目标：解决"同一指标因医院不同、单位不同、测定方法不同而无法统一比较/画趋势"的问题。

---

## 1. 问题背景

当前 `labs` 表平铺存储：`name`（项目名）、`value`、`unit`、`low`、`high`、`flag`。

实测暴露的痛点：
- **同指标不同写法被拆成两条**：`25羟基维生素D[25(OH)D]` 与 `25OH维生素D 25OHVitD`、OCR 错字 `nq/ml`，都会让趋势图把同一指标画成多根线。
- **单位不一致**：血糖 `mg/dL` vs `mmol/L`、胆固醇 `mg/dL` vs `mmol/L`、血红蛋白 `g/L` vs `g/dL`，直接连线会得到数量级错误的"趋势"。
- **测定方法不同**：如维生素D 电化学发光法 vs LC-MS/MS、HbA1c 的 IFCC vs NGSP，数值与参考区间本就不同源，不能简单混比。

医学检验"可比较"必须**同时对齐三个维度**：同一指标（analyte）、同一单位（换算到基准）、同一方法（或显式标注不可比）。缺一即失真。

---

## 2. 目标与非目标

### 目标
- 同一指标在**不同写法**下能归并（同名归一）。
- 不同单位能**换算到统一基准单位**后再画趋势。
- 原始值、原始单位、测定方法**完整保留**，详情可见。
- 无法换算 / 方法不可比的数据**不强行混线**，显式提示。
- 兼容既有 ~70 条数据，迁移可回溯。

### 非目标（本次不做）
- 不做完整 LOINC 全库映射（仅在字典里留可选 `loinc` 字段挂载）。
- 不做跨成员的指标合并。
- 不做自动 OCR→指标字典的智能匹配（AI 解析仍输出原始 name，映射走字典别名表 + 人工确认）。

---

## 3. 数据模型设计

### 3.1 指标字典表 `lab_analytes`（新表，静态或可编辑）
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PK | 标准指标内部 key，如 `vitamin_d_25oh`、`glucose`、`ldl_c` |
| `name_std` | TEXT | 标准展示名，如「25-羟基维生素D」 |
| `category` | TEXT | 分组，如 生化/血脂/血常规/糖代谢 |
| `base_unit` | TEXT | 基准单位（趋势统一用），如 `ng/mL`、`mmol/L`、`g/L` |
| `loinc` | TEXT NULL | 可选，LOINC 码（留作未来互通） |
| `methods_note` | TEXT NULL | 方法学提示，如"不同方法参考区间不同，谨慎对比" |
| `note` | TEXT NULL | 备注 |

### 3.2 指标别名表 `lab_analyte_aliases`（新表）
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PK | |
| `analyte_id` | TEXT FK→lab_analytes.id | 归属标准指标 |
| `alias` | TEXT | 原始写法（含常见 OCR 错字/英文缩写/带标本后缀写法） |
| `normalized` | TEXT | 归一化后的匹配键（去空格、全半角、标点、大小写） |

> 匹配顺序：先精确 `normalized` 命中，再模糊（去括号内容/去 `*` 前缀）命中，最后未命中 → 标记 `unmapped`，前端提示"未识别指标，请手动归并"。

### 3.3 单位换算规则表 `lab_unit_conversions`（新表）
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PK | |
| `analyte_id` | TEXT FK | 归属指标 |
| `from_unit` | TEXT | 原始单位，如 `mg/dL` |
| `to_unit` | TEXT | 目标单位（= base_unit），如 `mmol/L` |
| `factor` | REAL | 乘数（value_std = value_raw * factor） |
| `offset` | REAL default 0 | 平移（适用于非线性/温度类，线性类为 0） |

> 换算只对"同指标已登记 from_unit"生效；未登记的 from_unit → `value_std = NULL` 并标 `unit_unconverted`。

### 3.4 `labs` 表新增字段（向后兼容，NULL 允许）
| 字段 | 类型 | 说明 |
|---|---|---|
| `analyte_id` | TEXT NULL | 归一后的标准指标 key；空=未映射 |
| `unit_raw` | TEXT NULL | 原始单位（保留医院原文） |
| `value_raw` | REAL NULL | 原始数值（= 现在的 value） |
| `value_std` | REAL NULL | 换算到基准单位后的值（趋势用） |
| `method` | TEXT NULL | 测定方法（保留报告原文，如"电化学发光法"） |
| `low_std` / `high_std` | REAL NULL | 换算后的参考区间（随值一起换算） |
| `std_status` | TEXT | `ok` / `unmapped`(指标未识别) / `unit_unconverted`(单位未登记) / `qualitative`(定性) |

> 保留 `value`/`unit`/`low`/`high` 原字段不动，避免破坏现有读取方；新字段是"标准化视图"。

## 4. 换算引擎（纯函数，后端）

```
standardize_lab(lab):
  analyte = match_analyte(lab.name)            # 别名表，命中→analyte_id
  if not analyte: return {std_status:'unmapped'}
  if lab.value is None or lab.qualitative: return {std_status:'qualitative'}
  conv = find_conversion(analyte, lab.unit)
  if not conv: return {std_status:'unit_unconverted', analyte_id:analyte.id}
  value_std = lab.value * conv.factor + conv.offset
  low_std  = lab.low  * conv.factor + conv.offset  (low 非空时)
  high_std = lab.high * conv.factor + conv.offset  (high 非空时)
  return {analyte_id, value_std, low_std, high_std, std_status:'ok'}
```

- 幂等：可对全表重跑。
- 触发点：① 数据导入/编辑保存时；② 提供 `POST /api/labs/restandardize` 批量重算（改字典后可全量重跑）。
- 只读派生：`value_std/analyte_id` 等由原始字段派生，字典变更后可重建，不丢原始数据。

## 5. 趋势图（前端）改造

- **趋势只画 `value_std`**，X 轴日期、Y 轴统一基准单位。
- **按 analyte 选择**：指标下拉/筛选以 `analyte_id` 分组，而不是原始 name。
- **参考带**：用 `low_std/high_std` 画正常区间带。
- **方法/标本混入提示**：若同指标下存在多种 `method`（或 method 为空但来源不同），在图上方显示软提示"含多种测定方法/来源，已按标准单位对齐，仅供参考"，并可在详情分组查看。
- **不可标准化数据**：`std_status != ok` 的点不进入连线图，但在列表/详情中以标注形式展示原值，提示"单位/指标待核对"。
- 详情弹层展示：原始值+原始单位+测定方法+来源医院（已有）+ 标准值（换算后）+ 换算说明。

## 9. 风险与权衡
- **换算系数错误风险**：系数必须逐条核对，错一个就整体失真 → 用基准单位标注 + 原始值并列展示兜底。
- **方法学不可比**：不做"数值强行统一到某方法"，只做单位换算 + 方法透明标注，避免制造虚假可比。
- **LOINC 暂不深接**：留字段不引入大工作量；将来若要多端互通再补映射。
- **OCR 脏数据**：`nq/ml` 之类错字，靠别名表 + 人工确认兜底，不自动猜。
