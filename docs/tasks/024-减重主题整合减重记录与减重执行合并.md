# 024 减重主题整合：减重记录 + 减重执行 合并为「减重」大主题

- **优先级**：P1
- **类型**：前端信息架构（IA）整合，零数据迁移
- **关联**：023（病历信息架构整合）、009（体重/体脂字段）、013（减重执行数据闭环）

## 背景与决策

当前「减重」相关有两块独立入口，并列在左侧导航顶级：

- **减重记录**（`weight` 路由 → `renderWeight()`，`js/app.views.body.js:170`）：体重趋势图、身体成分、腰围、体重明细表（分页/折叠）、称重与记录规则、当前计划。核心数据 `state.weights`（体重 kg + 6 项身体成分）。
- **减重执行**（`diet` 路由 → `renderDiet()`，`js/app.views.body.js:635`）：每日记录（饮食/晨重/摄入范围/完整度）、每周复盘、提醒、执行趋势。核心数据 `dietDays` / `dietWeeks`（localStorage：`personal-health-diet-days-v1` / `-weeks-v1`，`js/app.core.js:50-51,88-89`）。

**问题（与 023 同构）**：

1. **入口分散**：同一主题被拆成两个顶级导航项，用户需在两个页面间来回切换才能看清"体重变化 ↔ 饮食执行"的关系。
2. **双份体重**：`state.weights`（体重记录）与 `dietDays[].morningWeight`（每日晨重）是**同一事实的两次录入、两处展示**。`renderDiet` 的"晨重"趋势（`dietTrendPoints('morningWeight')`）与 `renderWeight` 的体重趋势说的是同一件事，但互不引用。
3. **无主题归属**：与 023 的"病历"分组一致，减重在数据与心智上是**一个主题（体重管理）**，缺一个统一的落地页把它组织起来。

**决策：合并为一个「减重」大主题（IA 层），不合并底层数据模型。**

- 保留 `state.weights` 与 `dietDays/dietWeeks` 两张数据各自独立存储（同 023：不强行合并实体，避免破坏数据与迁移）。
- 在导航上用 `group: '减重'` 把两块收进一个分组（复用 023 已建立的 `.nav-group` 机制），或合并为单个路由 `sl-im` 下的**分段视图（tabs/段）**。**推荐后者**：单一「减重」入口，页内分「概览 / 体重与身体成分 / 饮食执行 / 每周复盘」几段。
- 页内以"体重"为主线串联：概览段聚合当前体重、进度、近 7 天、摄入中心、记录完整度，作为两块数据的统一落地。

## 范围

**做**：

1. 新增统一入口「减重」（路由 id 建议 `weight`，即把 `diet` 内容并入 `weight`，或新增 `sl-im` 聚合页；具体方案实施时择优）。
2. 页内分区（tab 或锚点段）：
   - **概览**：当前体重 / 较起点 / 目标进度 / 近 7 天记录 / 近 7 天摄入中心与完整度 —— 从 `weights` 与 `dietDays` 汇总。
   - **体重与身体成分**：原 `renderWeight` 的英雄区、体重趋势图、身体成分、腰围、明细表（分页+折叠）、称重规则、计划。
   - **饮食执行**：原 `renderDiet` 的每日记录表、提醒。
   - **每周复盘**：原 `renderDiet` 的周复盘表。
3. 导航：`weight` 与 `diet` 两项合并为一项「减重」（若保留两个 hash 兼容旧链接，则 `diet` 301/redirect 到 `weight#diet` 段，`#/diet` 仍可达）。
4. 顶部 hero 与图表统一走 `echartsChart`（已具备）。
5. 概览段对"双份体重"做**只读说明**：明确 `晨重`（diet 每日）与 `体重记录`（state.weights）的口径差异（标准晨重 vs 其它条件），不做自动合并、不互相覆盖。

**不做（非目标）**：

- 不改 `state.weights`、`dietDays`、`dietWeeks` 的数据结构与持久化键。
- 不改 `server/health_server.py`、DB schema、`/api/*` 契约。
- 不做体重数据自动去重/迁移（双份并存是有意的口径区分）。
- 不动其它主题。

## 验收

1. 左侧导航只有一个「减重」入口，点击进入统一页；`#/diet` 旧链接仍能落到饮食执行段（不 404）。
2. 统一页四个分区齐全，数据取自原有 `weights` / `dietDays` / `dietWeeks`，增删改功能（记录体重、记录今天、写周复盘、编辑/删除）全部保持可用。
3. 图表（体重趋势、晨重趋势、摄入趋势）正常渲染，`dataZoom` 缩放可用。
4. `node --check` 全部 JS 通过；`server/` 零改动；HTTP 冒烟页面 200。
5. 现有数据零丢失：打开后 weight 明细与 diet 每日/每周记录条数与合并前一致。
6. 改动分阶段、独立 commit，`git commit` 不 push。

## 风险与回滚

- **风险**：合并路由时旧 `#/diet` 书签失效 → 用路由别名保持兼容。
- **风险**：hero 汇总把两套体重口径混算，误导用户 → 概览段显式标注口径，不做数值合并。
- **回滚**：改动集中在 `js/app.views.body.js`（新增聚合渲染）、`js/app.views.health.js`（NAV）、`js/app.boot.js`（ROUTES/跳转）；单独 revert 提交即可恢复两页。
