# 小米健康数据导入 SQLite —— 表结构设计

> 数据源：`data/小米健康数据/`（两个导出包：`…mi_finess_eco_data_copy` 体脂秤 + `…MiFitness_c3_data_copy` 手环/健康中心）
> 目标库：`data/health.db`
> 导入脚本：`Tools/import_xiaomi.py`
> 导入批次号：`xiaomi-20261029`

---

## 一、设计原则

1. **不污染现有业务表**：小米数据落入 `mi_` 前缀表；同时对**体成分 → `weights`、睡眠 → `sleep_log`** 做同步写入，让前端页面无需改动即可展示。
2. **原始保真**：所有 `Value` 原始 JSON 全量存 `mi_raw_metric`，防字段丢失，可随时重新解析。
3. **可重复导入（幂等）**：每次导入先按 `batch` 删除再全量重灌，不 `DROP` 表、不破坏手工录入数据。
4. **秒级时间戳统一**：源数据 `Time`/`time` 多为 Unix 秒（部分自动识别毫秒），统一转 `INTEGER`（秒）+ `TEXT date`（YYYY-MM-DD）。

---

## 二、源文件与用途

| 源 CSV | 行数 | 用途 |

## 三、表结构

### 3.1 `mi_body_composition` —— 体成分（体脂秤）
来源 `eco_scale_record.csv`，**418 行**，时间范围 2024-03-04 ~ 2026-07-24。

| 列 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| batch | TEXT | 导入批次 |
| record_key | TEXT | `device_id|time` 去重键 |
| device_id / device_model | TEXT | 设备标识（yunmai.ms103） |
| user_id | TEXT | 用户 ID |
| ts / date / time_str | INTEGER/TEXT/TEXT | 秒级时间戳 / 日期 / HH:MM |
| weight_kg | REAL | 体重 kg |
| bmi | REAL | BMI |
| body_fat_pct | REAL | 体脂率 %（源 `bfp`） |
| muscle_pct | REAL | 骨骼肌率 %（源 `slm`） |
| muscle_kg | REAL | 骨骼肌量 kg（源 `smm`） |
| water_pct | REAL | 体水分率 %（源 `bwp`） |
| bone_kg | REAL | 骨量 kg（源 `bmc`） |
| protein_pct | REAL | 蛋白质率 %（源 `pp`） |
| visceral_fat | REAL | 内脏脂肪等级（源 `vfl`） |
| bmr | REAL | 基础代谢 kcal（源 `bmr`） |
| body_age | REAL | 身体年龄（源 `ma`） |
| body_score | REAL | 身体得分（源 `bodyRes`，设备原始值） |
| fat_mass_kg | REAL | 脂肪量 kg（源 `bfm`） |
| fat_free_kg | REAL | 去脂体重 kg（源 `ffm`） |
| muscle_mass_kg | REAL | 蛋白质量（源 `pm`/`bwm`） |
| water_kg | REAL | 水分量 kg（源 `swt`） |
| heart_rate | REAL | 称重心率 |
| raw_json | TEXT | 原始整行 |

> **注意**：部分记录为「不完整称重」（如只测体重、`bfp/bmi`=0），属源数据本身缺失，非导入问题。有完整体成分的记录约 87~272 条。

### 3.2 `mi_daily_activity` —— 每日活动汇总
来源聚合文件 `daily_report` 类，**1,298 天**，2022-06-01 ~ 2026-10-29。主键 `(batch, date)`。

| 列 | 类型 | 说明 |
|---|---|---|
| batch / date | TEXT | 主键 |
| ts | INTEGER | 当日时间戳 |
| steps | INTEGER | 步数（日均约 5,273，最高 34,556） |
| distance_m | REAL | 距离 米 |
| calories | REAL | 步数附带的消耗 |
| active_cal | REAL | 活动热量 |
| stand_count | INTEGER | 有效站立次数 |
| intensity_min | INTEGER | 中高强度分钟 |
| goal_cal / goal_steps / goal_stand | REAL/INT | 当日目标（源常缺） |
| payload_json | TEXT | 当日各 Key 的原始 Value 汇总 |

### 3.3 `mi_sleep` —— 睡眠（夜间主睡眠）
来源聚合 + 原始明细合并，**1,156 晚**，2022-06-01 ~ 2026-10-28。主键 `(batch, date)`（归属日=起床日，同日取时长最长的一条）。

| 列 | 类型 | 说明 |
|---|---|---|
| batch / date | TEXT | 主键 |
| bedtime_ts / wake_ts | INTEGER | 入睡/起床时间戳 |
| bedtime / wake | TEXT | HH:MM（从 segment_details 提取） |
| total_min | REAL | 总睡眠分钟 |
| deep_min / light_min / rem_min / awake_min | REAL | 各阶段分钟 |
| score | INTEGER | 睡眠得分 |
| avg_hr | REAL | 平均心率 |
| snore_min | REAL | 打鼾时长 |
| segments_json | TEXT | 睡眠分期原始片段 |

### 3.4 `mi_heart_rate` —— 心率散点
来源原始明细 `single_heart_rate`/`dynamic`，**6 条**（该导出心率点极少）。

| 列 | 类型 | 说明 |
|---|---|---|
| id / batch | INTEGER/TEXT | 自增 / 批次 |
| ts / date / time_str | INTEGER/TEXT/TEXT | 时间 |
| bpm | REAL | 心率 |
| kind | TEXT | 来源类型（single_heart_rate/dynamic） |

### 3.5 `mi_raw_metric` —— 原始指标全量
**14,473 条**，保存聚合文件全部 Key + 原始文件的少量特殊 Key（心率类）。

| 列 | 类型 | 说明 |
|---|---|---|
| id / batch | INTEGER/TEXT | 自增 / 批次 |
| key | TEXT | 指标名（steps/sleep/calories/valid_stand/intensity/goal/headset/weight/heart_rate/single_heart_rate/dynamic） |
| tag | TEXT | 分组（daily_report/daily_mark/daily_fitness） |
| sid / ts / date | TEXT/INT/TEXT | 会话 / 时间 |
| value_json | TEXT | 原始 JSON |
| update_time | INTEGER | 更新时刻 |

### 3.6 `mi_profile` —— 个人资料快照
**1 行**。

| 列 | 说明 |
|---|---|
| batch (PK) / uid / name / sex | 批次 / 用户 / 性别 |
| birth / height_cm / weight_kg / region | 生日 / 身高 / 体重 / 地区 |
| max_hr / daily_cal_goal / daily_step_goal / daily_sleep_goal_min | 最大心率 / 每日目标 |
| raw_json | 原始档案 |

## 四、与业务表的同步

| 小米表 | → 业务表 | 规则 |
|---|---|---|
| `mi_body_composition` | `weights` | 每条形如 `id=xiaomi-20261029-bc-<ts>`，写入 kg/body_fat/muscle/bmi/visceral_fat/bmr/bone，tag=`device`。**不动手工录入的 weights 行。** |
| `mi_sleep` | `sleep_log` | 每夜形如 `id=xiaomi-20261029-sl-<date>`，写入 hours/minutes/score/bedtime/wake，source=`xiaomi`。 |

前端 `GET /api/all` 的 `weights` 和 `sleepLogs` 字段即自动包含这些数据，页面无需改动。

## 六、重复导入 / 用法

```bash
# 语法检查后执行（幂等，可反复跑）
server\.venv\Scripts\python.exe Tools\import_xiaomi.py

# 只看统计不写库
server\.venv\Scripts\python.exe Tools\import_xiaomi.py --dry-run
```

重新导入时按 `batch=xiaomi-20261029` 删除旧记录后重灌，`weights`/`sleep_log` 中以 `xiaomi-20261029-` 前缀的记录会同步刷新，**手工数据不受影响**。

## 七、局限与后续可选

- `intensity_min`（中高强度分钟）在聚合数据里绝大多数为空，源数据本身稀疏。
- 心率仅 6 个散点，无法做心率曲线；如需可在后续解析 `fitness_data.csv` 的 `dynamic` 血流/心率序列。
- 饮食、运动路线、训练计划等 CSV 为空，未入库；若日后有数据可扩展 `mi_diet`、`mi_workout` 表。
- `body_score` 存的是设备 `bodyRes` 原始值（非 0-100），如需归一可再映射。
