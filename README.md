## 目录结构

2026-10-30 做过一次目录整理，2026-11 再次调整，把「个人健康数据」「工程文档」「界面设计稿」彻底分开。现在内容根如下：

```
F:/Health/
├─ index.html        档案应用入口（双击打开）
├─ assets/           应用代码：样式、档案数据、解析引擎、路由
├─ server/           可选的图片识别服务（本机 127.0.0.1:8765）
├─ Tools/            脚本：解析回归、端到端测试、影像分析、链接检查
├─ docs/             工程文档：Markdown 底稿 + 生成的 HTML 页面（可进 Git）
├─ design/           界面设计稿：原型图、空态设计稿（工程产物，可进 Git）
├─ private_data/     个人健康记录：病历、就诊、检验转写、减重记录等（不进 Git）
└─ data/             健康数据根：数据库、报告原件照片、影像、导出的 CSV —— 不进 Git
```

分开的理由：**工程代码/文档/设计稿可以进版本库、可以发给别人看；个人健康数据不行**。放在同一个目录里，一次误提交就会把照片和原始导出带上。

- `data/` 是「健康数据根」：只放数据库、报告原件、影像、导出 CSV 这类实际健康数据与原件，`data/设计稿/` 已迁出。
- `design/` 是「界面设计稿」，属于项目工程产物，与个人健康数据、工程文档都分离。
- `private_data/` 是「个人健康记录」（病历、就诊、检验转写、减重记录等），不进 Git，仅放行 `_meta/` 结构配置。
- `.gitignore` 已默认忽略根目录下一切未放行的条目（`data/`、`private_data/` 内容、杂项）。

## 文档：docs/

| 位置 | 放什么 |
| --- | --- |
| `docs/使用指南.md` | 界面怎么用、四条录入通道、数据存哪、常见问题 |
| `docs/个人健康档案产品与技术规划.md` | 当前能力评估、跨端技术路线、数据同步与迁移、分阶段交付及验收；可直接阅读同名 HTML |
| `docs/HANDOFF.md` | 交接说明：架构、数据模型、关键决策、已知坑、待办与验收命令（给接手维护的人看） |

`docs/` 只放**工程/产品文档**：使用指南、规划、架构、更新日志、HANDOFF、数据表结构说明等。个人健康记录（个人资料、健康问题总表、用药记录、检查与就诊时间线、复诊与待办、减重记录、各主题原始记录与分析等）已全部迁到 `private_data/`，与工程文档分离，不进 Git。要看这些记录，直接打开 `private_data/` 下对应目录，或在页面里跳转。

每个 `.md` 旁边有一份同名 `.html`，是给人直接看的渲染版（`Tools/生成HTML档案.cjs` 生成，已有 HTML 不覆盖）。改内容改 `.md`，需要时重新生成 HTML。

## 数据：data/

| 位置 | 放什么 | 是否进 Git |
| --- | --- | --- |
| `data/health.db` | **页面里录入的全部数据**（检验、体重、围度、勾选、报告索引），SQLite 库文件 | 否 |
| `data/报告原件/files/` | 页面里存的报告照片，一份报告一个文件，文件名是报告 id | 否 |
| `data/报告原件/` | 原始化验单照片，以及挂在外面的转写稿；文件名 `日期-机构-项目.jpg` | 否 |
| `data/照片/` | 症状照片（如舌苔、皮损），文件名 `部位-日期.jpg` | 否 |
| `data/右脚踝/检查/` | 医院给的原片（DICOM），一次检查一个目录 | 否 |
| `data/右脚踝/<分析>/` | 由原片渲染出的切片图、序列汇总 JSON、关键图 | 否 |
| `data/小米健康数据/` | 手环/体脂秤导出的原始 CSV 包，保持导出时的目录结构不动 | 否 |

`data/` 里的东西是**原件、数据库与派生物**，不是档案结论。结论写在 `docs/` 的 Markdown 里，指向这里的具体文件。删掉 `data/报告原件/` 里的照片，页面记录还在但会失去可追溯的原件；删掉 `data/health.db` 则是记录本身没了。

## 界面

`index.html` 是单页档案应用，侧栏提供首页、就医记录、指标趋势、日常健康、健康主题、AI 问答与设置。侧栏默认收起为图标，可手动展开。点击「我的」打开档案浮层，切换或新增家庭成员，并进入成员管理、个人资料与数据；手机底栏共用「我的」入口。

检验指标页下面还有一个子页「全部记录」（`#/labs-all`）：检验页的「最近录入」只放 8 条，这里才是全部结果，按日期分组，可按项目/备注/医院搜索、按类别与来源报告筛选，每条都能编辑或删除。入口在检验页页头「全部记录」与「最近录入」右上角。

- 只读内容（主题、证据、时间线、用药）来自 `assets/data.js`，它是 `docs/` 下 Markdown 的结构化摘要。改内容要两边都动：先改 Markdown，再同步 `data.js`。
- 可写内容（检验结果、体重记录、身体围度、待办勾选、报告原件）存在**本机 SQLite 数据库** `data/health.db`，报告照片存成 `data/报告原件/files/` 下的真实文件。启动方式：双击根目录 `启动健康档案.bat`，浏览器会打开 `http://127.0.0.1:8765/`。
- 为什么不再用浏览器存储：localStorage 上限约 5 MB，报告照片一多就撑爆；换浏览器、清站点数据就全没了。数据库没有这个限制，换浏览器也不影响。
- 只有一份数据：不在浏览器里留副本。反过来，删掉 `data/health.db` 就真的没了——请定期用「导出完整备份」或在磁盘层面备份 `data/` 目录。
- 降级行为：服务没启动时页面仍能打开，但会退回浏览器存储并明确提示（侧栏显示「浏览器存储模式」）。这不是同一份数据，只是应急；连上服务后可在「个人资料 → 数据存储」里点「合并浏览器数据」把它并进库里（按日期｜类别｜项目｜单位去重，点两次不会翻倍）。
- `?offline=1` 参数强制浏览器存储模式，自动化测试用它避免把测试数据写进真库。
- 备份（`health-archive` v2）含检验、体重、围度、勾选状态与报告原件图片；服务模式下由 `/api/export` 生成，把磁盘上的图片读回 base64。导入按记录 ID 合并，再按项目去重，也兼容只有 `labs` 的 v1 备份。
- 界面文件：`assets/styles.css`、`assets/data.js`（档案内容数据）、`assets/parse.js`（报告解析）、`assets/app.js`（路由与交互）。
- 服务文件：`server/health_server.py`（页面 + 数据库 + 识别）、`server/health_features.py`（多模态解析、问答与成员）、`server/health_mcp.py`（agent 桥接）、`server/.venv/`（依赖，不进 Git）。只监听 `127.0.0.1`，不对外。

## 导入数据

四个通道（都在弹层里；文本与 CSV 解析在本机完成，图片解析连接配置的多模态模型）：

- 粘贴文本：把医院 App 或体检报告的文字复制进来，自动识别项目名、数值、单位、参考范围和日期；识别结果先进预览表，逐行确认后才写入。
- 图片识别：选报告照片，直接交给配置的多模态模型解析（见下）。识别结果会填进文字框，可以改错字再解析。
- CSV 文件：体检中心导出的表格，需含「项目」和「结果」两列表头（Excel 请先另存为 CSV）。
- JSON 备份：整库恢复或只导入其中一部分。先按记录 ID 合并，再按「日期｜类别｜项目｜单位」去重——同一项以文件里的为准，重复导入不会翻倍。

预览表里低置信度的行（缺单位、缺参考范围）默认不勾选，需人工看过再勾。同一天、同项目、同单位的记录会按“更新”处理，重复导入不会翻倍。报告没印单位时，勾选后按 `—` 记录（不编造单位）；没印参考区间就留空，趋势图不画色带，图例写「N 次无参考区间」而不是「均正常」。

已适配医院报告的常见形态：行首序号、`*` 互认标记、方法学括注（`项目名(酶法)`）、尾部英文缩写（`项目名 ENG`）、双横线区间（`下限--上限`）、页脚两位年份采样时间（`YY-MM-DD`，自动补全世纪）。正文日期优先于弹层里填的默认日期。报告写「标本类型」时会据此判类别——尿里的白细胞、红细胞归到「其他」，不会混进血常规。定性结果（阴性/阳性/normal）不进数值库，会列在「跳过」清单里说明原因。

解析引擎在 `assets/parse.js`（纯函数，可独立测试）。回归用例：`Tools/test-parse.cjs`（70 项）、`Tools/e2e-import.js`（25 项）、`Tools/e2e-report.js`（24 项，报告原件）、`Tools/e2e-ocr.js`（19 项，图片识别）。

## 多模态报告解析（可选）

报告图片直接交给配置的多模态模型读取，主服务不再加载 RapidOCR 或 ONNX Runtime。启动只需 Python 标准库，无须安装本地 OCR 依赖。历史 OCR 脚本仅留作旧版本参考。

在「设置 → 模型连接」选择 Magpie 或自定义 API，保存后立即生效。也支持通过 `HEALTH_AI_URL`、`HEALTH_AI_MODEL` 与可选密钥设置启动默认值。模型须支持 Chat Completions 的 `image_url` 输入。使用远程服务时，报告图片会发送至该服务；界面会明确提示。未配置模型时，其余手工录入、文本/CSV 导入和档案功能仍可使用。

模型输出经本机预览表核对后保存，不自动当成确诊或可信测量值。「存一份报告」页可保留模型解析文字；AI 问答也能直接查看当前成员最多 3 张相关报告图片，不要求先转成文字。详细数据范围见 [AI 与多人档案](docs/AI与多人档案.md)。

## 报告原件

检验页「报告原件」卡：

- 每份报告登记日期、名称、机构、备注，可选一张原件图片（拍照或截图，自动压到长边 1500px 后存进本机数据库旁的 `data/报告原件/files/`）。
- 报告有三层名称，由具体到笼统：**报告名称**（医院打印的申请项目，如「肝肾常规」）→ **项目组套**（大类，如「生化」「血常规」）→ **检验样本**（血清 / 血浆 / 全血 / 尿液 …）。后两项是自由填写 + 候选列表，报告没写就留空，不推测。
- 从图片识别或粘贴文本导入时，报告表头里的「标本类型」「申请项目」会自动预填到新建报告表单，预填值可改；没有这两行就空着。
- 导入结果时在预览页选「归到」哪份报告，单个录入/编辑时也有「所属报告」下拉；不关联也可以，表格里显示 —。
- 「最近录入」表的「报告」列可点开原件；删除报告不会删除结果，只解除关联。
- 走「图片识别」导入时，预览页选「＋ 新建一份报告」会把刚才的照片一起存成原件，不用再传一次。
- 图片不受浏览器配额限制（存 SQLite 旁边的真实文件），只受磁盘空间限制。原始照片另存在 `data/报告原件/`，与应用里那份互不依赖。

表格里的「提示」是单独一列：`↑` 高于参考上限、`↓` 低于下限、`·` 在区间内、`—` 未填参考范围无法判断。超范围只影响这一列的符号与数值颜色，不会塞进结果数字里。

空状态不填假数据：没有检验结果时图表为空，可点“预览示例”查看样式，示例不会写入存储。

## 更新约定

1. 日常新增饮食、体重与活动，写入当月减重记录；每周填写一次复盘。
2. 就诊或检查后，保存原件，补一条时间线，再更新问题总表、用药和待办。
3. 日期统一为YYYY-MM-DD；体重以kg为主，同时可写斤（1kg＝2斤）；能量统一用kcal（千卡）。
4. 明确区分“本人描述”“医院报告”“医生诊断”“辅助分析”“建议计划”。文件夹名称、空文件和未验证的推测不作为确诊依据。
5. 空白代表未记录，不等于没有症状、没有过敏或数值为0。历史用药不自动视为当前用药。
6. 页面上能直接改的内容（检验结果、体重、围度、待办勾选、报告原件）存在 `data/health.db` 里，`docs/` 的 `.md` 是文字底稿，两套互不同步；改了页面不会回写文件，改了文件也不会刷新页面。
7. **README、使用指南等说明性文件里不写任何个人健康信息**：不写指标数值、不写诊断与症状、不写体重、不写药名、不写机构名和就诊日期、不列带病名的目录。需要举例一律用占位符（`项目名`、`YYYY-MM-DD`、`下限--上限`、`机构`）。档案内容只留在档案文件与 `data/health.db` 里。
8. 新文件先判断归属：**看得懂、能公开**的进 `docs/`，**原件与导出**进 `data/`，**代码**进 `assets/` 或 `Tools/`。

本次以结构化记录整理档案，既有文字、报告、影像及其路径保留。各总表只做导航和摘要，详细表述以对应来源为准。
