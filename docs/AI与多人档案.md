# AI 问答、MCP 与多人档案

## 启动与成员

启动本机服务后，档案页面标明当前成员；设置为所有成员共用。点击侧栏或手机底栏的「我的」，在浮层中切换、新增档案；也可从浮层进入「成员管理」编辑称呼、关系，或进入「个人资料与数据」。切换前先保存或取消编辑。成员选择保存在当前页面 URL，不会改变其他浏览器标签页所查看的人。

原有数据库、报告和静态档案归属「我的档案」，升级不会搬迁或清空原数据。新增成员使用独立 SQLite 数据库与图片目录，不继承原成员的静态病史、减重目标、待办或浏览器缓存。可在「我的」内继续补充个人资料。

这是同一台电脑上管理多位家庭成员，不包含独立账号、远程登录、邀请或访问权限管理；能使用本机平台的人可以切换全部成员。不要把它当成面向不同用户的隔离登录系统。

默认数据保存在 `data/health.db`；其他成员位于 `data/health_members/<成员ID>/health.db`，报告图片在各成员目录内的 `files/`。成员清单位于默认数据库的 `members` 表。浏览器离线降级缓存也按成员区分。没有提供删除整个成员的入口。

JSON 导入、导出与页面内所有记录修改只针对当前成员。请分别为各成员导出备份；完整磁盘备份应包含整个 `data/`。AI 问答历史保存在各自数据库的 `ai_chat` 表，随数据库磁盘备份保存，目前不包含在 JSON 记录导出中。原有每日数据库滚动备份任务仍只备份默认数据库。

## 配置多模态模型

设置现按「常规、模型连接、MCP、关于」分类，左侧可搜索设置，右侧只显示当前分类；切换分类会保留尚未保存的表单输入。手机上分类导航显示为横向列表。推荐直接在页面「设置 → 模型连接」配置。Magpie 为默认选项；选择「自定义 API」后填写基础 URL（如 `https://api.example.com/v1`）或完整 Chat Completions URL、API 密钥和默认模型 ID，点击「保存连接」后立即生效，无须重启。

密钥留空可保留原密钥，勾选「清除已保存的密钥」可删除。更换 API 地址时须重新填写或明确清除密钥，避免把原服务的凭证发给其他地址。切回 Magpie 会保留自定义信息，方便之后再切换。

设置保存在数据库旁的 `<数据库名>.ai-settings.json`，包含本机保存的密钥，不会通过配置接口回显。所有成员共用模型连接。已保存的页面设置优先于环境变量；没有保存过时，可在 PowerShell 设置环境变量，再在同一终端启动服务：

```powershell
$env:HEALTH_AI_URL = 'http://127.0.0.1:11434/v1/chat/completions'
$env:HEALTH_AI_MODEL = '本机已安装且支持图片输入的模型名称'
$env:HEALTH_AI_KEY = ''
python server/health_server.py
```

模型服务需要支持 Chat Completions 格式：请求包含 `model` 和 `messages`，并支持多模态 `image_url` 内容，响应读取 `choices[0].message.content`。远程服务使用其提供的完整 HTTPS 接口地址和密钥。仅本机地址允许 HTTP。密钥保存在本机服务端配置中，也可由环境变量提供；配置接口不会回传密钥，前端不会保存密钥。

进入「AI 问答」提问。每个问题独立作答，不自动携带之前的对话；需要上下文时请写明日期、项目或报告名称。回答和本次检索来源会按成员保存，展开来源可以查看当时提供给模型的记录。

检索范围包含检验、报告文字与备注、就诊、用药、病史、体征及日常健康记录，每类最多 16 条；按问题关键词和日期排序，总上下文约 48,000 字符。原成员还可检索 `private_data/` 中的 Markdown 档案，最多 4 份，每份最多 5,000 字符。截取不保证覆盖全部历史；未检索到不代表没有。

报告图片直接提供给多模态模型，不依赖本地 OCR。「存一份报告」页面可以解析图片、核对文字并保存；保存时解析文字保留在报告备注中，多图时只关联到用于解析的那张原件。也可仅保存图片，之后在问答时让模型直接读图。

问答在当前成员检索出的报告中，最多附加 3 张图片（每张最多 4 MB，支持 PNG/JPEG/WebP/GIF）；来源会标注「已提供图片」。未提供图片的来源不能视为已读图。当前不直接读取 PDF 或 DICOM 像素，需转成受支持的图片。

配置远程模型后，每次提问会发送当前成员的相关健康记录、报告图片和称呼至该模型服务；页面会显示此提示。默认未配置模型，不会发送健康信息。回答用于信息整理与复诊准备，引用方便核对，不能保证模型解读正确，也不构成诊断或处方。

## Magpie 与对话模型列表

双击 `启动健康档案.bat` 默认连接本机 Magpie：`http://127.0.0.1:3425/v1/chat/completions`，默认模型为 `workbuddy/glm-5.3-flash`。先运行 Magpie，再启动健康档案。页面保存的连接设置优先；没有保存过时，使用 `HEALTH_AI_URL` 和 `HEALTH_AI_MODEL` 环境变量或默认 Magpie。

AI 对话页在输入框下方提供紧凑的模型下拉框，收起时显示简短名称，展开后按上游分组展示完整模型 ID。列表从模型服务的 `/v1/models` 获取，只展示标注支持图片输入的模型，可刷新。列表表示上游已公布的能力，实际调用仍取决于账号、额度及服务状态。列表获取失败时保留当前配置；不会逐个调用模型来消耗额度进行探测。

选择仅影响当前对话请求，不会修改其他标签页或报告解析的默认模型。回答历史会保存对应的模型名称。Magpie 是本机代理，健康记录及报告图片会继续转发至所选的上游模型服务。

## 连接 MCP

本项目提供 MCP stdio 服务，支持 2025-11-25 协议及常见旧版初始化协商，采用逐行 JSON-RPC。协议依据：[MCP 生命周期规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle)。

先启动健康档案，再从「设置 → Agent · MCP 连接」复制配置到 MCP 客户端。页面根据当前 Python、目录、端口和数据库生成配置，无须把访问凭证复制给模型。

桥接程序为 `server/health_mcp.py`，只连接本机 HTTP 服务。服务启动时在数据库旁生成 `<数据库名>.agent-token`，该文件留在不进 Git 的数据目录中。它授权 agent 操作全部家庭档案；保护它与健康数据库一样重要。自定义数据库或端口时，使用页面生成的 `--url` 和 `--token-file`。

| 工具 | 功能 |
| --- | --- |
| `list_profiles` | 列出成员及其 ID |
| `save_profile` | 创建成员；提供已有 ID 可改称呼、关系 |
| `read_archive` | 读取指定成员的结构化档案 |
| `upsert_record` | 新增一条记录，或按 ID 更新其部分字段 |
| `delete_record` | 按成员、类别、记录 ID 删除一条记录 |
| `ask` | 使用已配置模型回答指定成员的问题 |

所有记录操作必须显式提供 `profile_id`。先列出成员，确认所属人，再读写；不得从健康内容猜测患者身份。记录类别包含 `labs`、`reports`、`weights`、`body`、`vitals`、`symptoms`、`visits`、`medications`、`allergies`、`familyHistory`、`surgeries`、`dietDays`、`dietWeeks`、`sleepLogs`、`todoItems`。先读取档案了解实际字段；日期用 `YYYY-MM-DD`，数值用 JSON number，不补造健康信息。

写入是单条记录的合并操作，不会要求 agent 重传整表。删除报告会解除检验和就诊关联，删除就诊会解除用药关联。页面当前已加载的数据不会实时推送更新，agent 修改后刷新页面查看。
