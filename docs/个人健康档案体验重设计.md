# 个人健康档案体验重设计

设计日期：2026-11-01。状态：待评审，只做产品设计，未实施功能变更。

后续页面设计以 [Demo 页面结构与交互说明](Demo页面结构与交互说明.md) 为结构参考；视觉样式由用户重新设计。

## 1. 产品方向

从“维护一套完整的健康数据库”调整为“随手留下记录，需要时能找得到、用得上”。首次使用不要求补齐资料；每次记录不要求完成分类；详细整理允许延后。

首要场景：刚看完门诊，在一分钟内留下这次看病的信息；其次是收到报告后保存原件，以及日常快速记体重、血压或症状。时间目标是设计验收目标，尚未经过用户测试。

## 2. 当前问题与依据

基于现有导航、总览、就诊、录入与更多菜单的代码审查，而非真实用户可用性测试。

| 现状 | 带来的负担 | 设计决定 |
| --- | --- | --- |
| 侧栏有 11 个入口，只有部分按“病历”分组 | 用户需要理解各模块的区别 | 收敛为首页、就医记录、日常健康、健康主题；个人资料与工具放“我的” |
| 总览首屏大面积展示体重、BMI、减重目标 | 综合健康档案看起来像减重工具 | 首页以快捷记录、待办、最近记录为主，趋势放到日常健康 |
| 就诊一次展示日期、类型、科室、医院、医生、报告、主诉、诊断、小结、备注，共 10 项，只有日期必填 | 可选字段仍造成认知负担，填写人需要提前理解主诉/诊断/小结 | 默认日期 + 一段自由记录；其他信息渐进展开 |
| “记录一次”默认进入体重，页签没有就诊和症状 | 通用入口与实际任务不匹配 | 通用入口先选要记什么；场景入口直接打开对应表单 |
| 就诊、报告、用药和时间线分散 | 同一次看病需要往返多个页面 | 在“就医记录”中聚合查阅，在就诊详情中关联内容 |
| 空状态展示完整示例表，还可按占位示例新建 | 增加阅读量，容易留下占位内容 | 简短解释 + 一个主按钮，不把示例内容写入真实记录 |
| “更多”菜单另维护一套入口，覆盖不全 | 手机与桌面心智不一致 | 两端使用同一套模块；移动端底部五项，桌面“我的”置底 |
| 完整度与大量“待补”内容占据总览 | 每次打开都像有未完成作业 | 取消全局补齐压力；只有影响当前任务的缺项才提示 |

## 3. 信息架构

| 一级入口 | 默认内容 | 二级内容与边界 |
| --- | --- | --- |
| 首页 | 快捷记录、真正需要处理的事、最近记录 | 不堆放全部指标；无待办时隐藏待办区 |
| 就医记录 | 综合时间线 | 全部 / 就诊 / 报告 / 用药；就诊摘要在详情及模块工具中提供 |
| 日常健康 | 最近使用的记录类型，初次默认体重 | 体重与饮食 / 血压等体征 / 症状 / 睡眠；各自记录与趋势在同一页 |
| 健康主题 | 用户主动关注的问题 | 按主题汇总相关就诊、报告、症状及计划；不要求录入前先建主题 |
| 我的 | 基础资料、过敏等重要信息 | 备份与恢复、设备数据导入、存储位置、使用帮助 |

报告与用药支持独立存在，不强制挂到一次就诊。时间线是查看方式，不让用户另填一条时间线。主题是可选组织方式，不是录入门槛。页面聚合不代表把不同类型记录合并成同一种数据。

移动端底部：首页、就医、日常、主题、我的；桌面保留文字侧栏，不再把所有二级内容常驻侧栏。待办入口在首页“全部待办”，就诊详情中也能新增相关提醒。

## 4. 首页

从上到下：

1. 标题“健康档案”与全局搜索，右侧“记一笔”。搜索覆盖原件名称、自由记录、医院、药名、指标。
2. 三个明确的常用动作：“记一次就诊”“存一份报告”“记日常数据”。不用先选所属模块。
3. “接下来要做”：到期与用户主动置顶的提醒，最多三项；显示日期、事项、完成操作和全部入口。没有内容则隐藏，不凭空生成复查安排。
4. “最近记录”：动态数据与历史档案合并按事件时间排列，显示类型、日期、一句摘要、来源；能打开原记录。不能只读取静态时间线，否则刚保存的门诊不会出现。
5. 可选“我关注的”：最多两个主动关注的主题或指标；由用户选择，默认不展示一整屏减重指标。

新用户首页：一句“从第一次记录开始”，提供上述三种动作；不要求先填姓名、身高、目标等资料。过敏等重要信息在首次用药/就诊摘要场景中做可跳过的相关引导。

## 5. 核心流程：记一次门诊

### 默认速记

- 标题：记一次就诊。
- 日期：默认今天，可修改，日历完整显示年月日。
- “这次看病，记下什么？”：一段自由记录，允许直接粘贴病历或医嘱。提示“看病原因、医生怎么说、下一步安排，记得多少写多少”。不强迫用户拆成主诉、诊断、小结。
- “补充就诊信息（选填）”：默认折叠，包含医院、科室、医生、就诊类型。类型默认门诊但明确可见于折叠摘要，不能推断具体机构或医生。
- “补充诊断与医嘱（选填）”：默认折叠，包含就诊原因、医生明确诊断、医嘱。不把自由记录自动当作确诊。
- “添加资料（选填）”：拍照、文件或关联已存报告。独立报告不必为了保存而新建一次就诊。
- 主按钮：“保存记录”。底部辅助文案：“以后随时可以补充”。

有效记录最低要求：有效日期 + 一段非空记录，或有效日期 + 至少一份附件；展开专业字段后，填写了就诊原因/诊断/医嘱也视为有内容。只选日期不能产生空记录。旧记录仍可查看，不能借新规则删除历史内容。

速记是正式记录，不一律标成“待完善”。它有真实内容就有价值。只有用户主动点击“稍后整理”，才进入待整理清单。

### 有病历照片时

在同一表单添加照片 → 保留原件 → 可选“从图片提取文字” → 查看原图与识别文字 → 用户确认后填入或保留原文 → 保存。

OCR 不是保存前提。识别不可用时仍可存原件；识别失败不丢附件。原文与用户修订内容可区分；不悄悄覆盖已有填写，不强行推断诊断、机构或日期。

### 保存以后

回到原来所在页面，并明确看到刚新增的记录。提示“已保存”，提供“查看记录”；二级可选动作：“加复诊提醒”“记这次用药”。不自动连续弹出表单。

关闭未保存内容时提供“继续填写 / 放弃本次内容”，后续再考虑自动保存本机草稿。保存失败保留所有输入；只有写入成功才能显示成功。存储降级到浏览器时清楚显示实际保存位置，不能让用户误以为已经进入主档案。

### 编辑已有记录

保留自由记录和全部结构化字段；摘要展示已有医院、类型等信息。展开后能查看已有值。折叠区域不是清空区域，保存速记不能覆盖原先填写的诊断、关联报告或用药。旧“就诊小结”可作为自由记录的初始内容，但旧主诉、诊断、备注各保留含义。

## 6. 就医记录与详情

列表采用纵向记录卡，减少宽表格。每条显示日期、类型、标题、两行摘要、资料数量；次要操作放到“更多”。桌面可提供可选表格视图，移动端保持卡片。

默认综合时间线，顶部按全部/就诊/报告/用药筛选，搜索与日期筛选按需使用。切换筛选不要求重新理解一组独立页面。相同来源的档案避免重复展示，保留来源可追溯。

就诊详情按顺序展示：本次记录 → 关联资料 → 本次用药 → 下一步安排 → 可展开的详细信息。用户在详情关联报告时，选择明确的记录，不按同一天自动建立关联。药物能跨多次就诊持续存在，记录就诊不会自动改变药物状态。

“导出给医生”集中在详情，先预览再导出，覆盖选定就诊、相关资料、当前用药与已记录的重要过敏信息；未知项标为未记录，不补为“无”。

## 7. 其他录入统一减负

| 动作 | 默认只展示 | 按需补充 |
| --- | --- | --- |
| 存报告 | 原件；日期可确认或留为未确认 | 名称、机构、类型；可选提取指标、关联就诊 |
| 记体重 | 今天、体重、测量条件 | 体脂、围度、肌肉量等；不能默认把所有记录标成晨重 |
| 记血压 | 今天、收缩压/舒张压、测量时段 | 心率、姿势、备注 |
| 记症状 | 今天、哪里不舒服/一句描述 | 程度、诱因、照片、关联主题 |
| 记用药 | 药名、状态；默认“待确认” | 剂量、频次、起止、关联就诊；不凭空补用法 |
| 加提醒 | 提醒内容、日期可选 | 类型、关联记录、重点标记；无日期不算逾期 |

资料导入与完整备份恢复分开命名：用户看见“存报告”“导入设备数据”“恢复备份”，不需要理解一个含多种格式的通用导入工具。

## 8. 视觉与文案

配色、字体、组件外观及具体排版由用户重新设计，原 Demo 的视觉样式不作为约束。保留信息优先级与交互减负原则。

每屏只突出一个主要操作；标题用日常语言：“就诊实例”改“就诊记录”，“主诉”在速记里不出现，“结构化保存”改“以后随时补充”。日期与类型作为记录的稳定定位信息。关键提示贴近当前动作，系统存储细节放我的与异常提示，不反复占据每个表单标题。

无报告、无诊断、无体重等状态分别说明“未记录”，不评价为不健康。去掉首页全档完整度百分比，保留我的中的可选资料清单。异常指标提示保留，避免把“少填字段”误做成隐藏已知异常。

## 9. 评审与验收目标

本轮只交付设计，以下用于后续验证，均不是已测量的结果。

- 新用户不看指南，能在首页找到就诊入口。
- 一段记录即可保存，不填写医院、医生、诊断也不被阻止。
- 目标：普通速记 30–60 秒完成；与当前流程做同任务对比。
- 有照片无文字时也能保存；OCR 失败不阻断。
- 保存后能在首页和就医列表立即找到同一条记录，再次编辑不丢旧字段。
- 同一次就诊中的原件、医嘱和用药可从一个详情页查看。
- 在手机上主要操作与默认字段不需要横向滚动。
- 在未填写过敏信息等情形中，不能显示“无过敏”等错误结论。
- 用五项任务验证可发现性：记门诊、存报告、记体重、找上次医嘱、看下次复诊安排。记录成功率、耗时、误入页面与放弃原因。

## 10. 后续实施顺序建议

第一批：门诊速记、保存后可见、首页动作入口、移除占位示例录入与补齐压力。第二批：一级导航收敛、就医综合列表与详情、日常记录的渐进表单。第三批：原件优先的采集、OCR 确认、可选整理与自定义关注。

优先验证一句话门诊是否足够、报告是否常常独立保存，再决定后续整理功能的深度。暂不增加费用管理、健康评分、AI 诊断、强制每日打卡等新负担。
