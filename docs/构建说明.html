文档构建说明（md → html）

本文件说明如何用一个入口把项目里的 Markdown 文档统一渲染为 HTML，替代过去“手工同步 / 经常忘记重新生成”的做法。对应任务 019（可维护性）。

一条命令搞定

# 完整构建：更新「健康问题总表」并重渲染 docs 下全部 .md 与根 README.md
node Tools/build-docs.cjs

# 只检查将处理哪些文件，不写盘、不跑子脚本（适合 CI / 提交前自查）
node Tools/build-docs.cjs --check

# 暂存构建：全部输出写到 build_test/ 下（不改动真实 docs，适合受限环境预览）
node Tools/build-docs.cjs --out=build_test

构建是幂等的：重复运行结果一致，不会产生重复内容，也不会改动数据库（对 data/health.db 只读）。

它做了什么

Tools/build-docs.cjs 把原先分散的三个脚本收敛为一个可重复运行的入口，按顺序执行：

  1. 从数据库派生「健康问题总表」 — 调用 Tools/生成问题总表.cjs（只读 data/health.db 的 labs 表，重写 docs/健康档案/健康问题总表.md 里的 AUTO 标记区块与「肝肾功能」行；异常严格按每条记录自身参考区间判定，不臆造）。
  2. 补齐主题档案结构 — 调用 Tools/生成主题档案.cjs（为 docs/主题/* 补齐「主诉 / 诊断 / 诱因 / 当前处置 / 复诊节点」五段并计算「档案完整度」；已有非空文件不加 --init 不改动）。
  3. 全域渲染 md → html — 用统一模板把 README.md 与 docs 下所有 .md 强制重新渲染为同名 .html（这一步修复历史上的“md 改了但 html 没跟上”的漂移）。

三个原脚本 保持不变（可逆、可单独调用）；build-docs.cjs 只是它们之上的统一编排 + 全域渲染补充。样式常量（CSS）只有一处来源：Tools/生成HTML档案.cjs 里的 const css = ...，build-docs.cjs 用正则读取它，避免两处 CSS 漂移。

覆盖范围与排除

  • 纳入渲染：根 README.md，以及 docs/**/*.md（含 docs/健康档案、docs/减重记录、docs/主题、docs/使用指南.md、docs/HANDOFF.md 等）。
  • 排除（内部文档，不生成对外页面）：
    • docs/tasks/** — 内部任务说明；
    • docs/产品缺口分析.md — 内部产品分析。
  • docs/健康档案/检验趋势.html 是自定义页面（配套 检验趋势.css / 检验趋势.js，没有对应 .md），渲染脚本只处理 .md，因此不会覆盖它。

app.js 拆分（同属任务 019）

原来约 2900 行的单体 assets/app.js 已按“视图”拆成 7 个经典脚本模块（共享全局作用域，无需打包器），放在 js/ 下，由 index.html 按依赖顺序加载：

文件 职责
js/app.core.js 基础工具 / 图标 / 数据模型与持久化
js/app.derive.js 派生数据 / 提醒 / 档案完整度
js/app.views.health.js 外壳 / 总览 / 健康问题 / 检验指标 / 全部检验 / 时间线 / 用药 / 待办
js/app.views.body.js 减重记录(体脂) / 生命体征 / 睡眠 / 症状 / 减重执行
js/app.views.profile.js 个人资料 / 就诊摘要导出
js/app.modal.js 弹层 / 表单 / 搜索 / 报告原件 / 导入 / OCR
js/app.boot.js 事件绑定 / 路由 / 启动
  • index.html 末尾按上表顺序用 <script src="js/app.*.js?v=..."> 依次加载（assets/data.js、assets/parse.js 仍在前面）。
  • assets/app.js 已改为空占位（仅保留说明注释），避免旧引用 404；实际逻辑全部在 js/ 下。
  • 拆分采用“按连续区间原样切分、不注入任何额外代码”的方式，7 个文件按序拼接后与原 assets/app.js 字节级完全一致（320255 字节，字节级校验 EQUAL=true），因此运行时行为与原文件完全相同；每个模块 node --check 均通过。

维护建议：改动某个视图时只改对应的 js/app.*.js，改完 node --check 该文件即可；事件绑定 / 路由集中在 js/app.boot.js。

受限环境提示（沙箱 / 低权限账户）

若运行账户对已存在的 docs 文件没有写权限（Windows 上报 EPERM / EACCES），脚本会跳过该文件并打印 [跳过] 无写权限，不会中途崩溃。此时可：

  • 用 --out=<目录> 把结果产出到暂存目录预览；或
  • 在具备正常写权限的账户 / 本机正常环境下运行 node Tools/build-docs.cjs。
