# 020 可维护性：视图层状态收敛 + 写入契约 + 并发与迁移演进

- 优先级：P1（接任务 019 之后的主线）
- 前置：任务 019 已完成前端领域/存储分层与服务端仓储/安全边界拆分。

## 背景

任务 019 解决了“规则与 I/O 无处安放”的问题，但视图层（`app.views.*.js` / `app.modal.js` / `app.boot.js`）仍通过全局兼容别名直接读写 `labs`、`state`、`reports` 等可变数组；任何文件都能改任何状态，渲染与持久化耦合在事件处理器里。这是当前最大的结构性耦合点。

## 目标与非目标

**目标**：单一内存 store、单向数据流、明确的写入契约，让“改一个视图不会碰坏另一个视图”。

**非目标**：不引入框架 / 虚拟 DOM / 打包器 / TypeScript 迁移；不改变 `file://` 可离线打开、SQLite 单真相、整表替换协议（千级数据量下够用）。

## 分阶段实施（每阶段独立可验收、独立提交）

### 阶段 1：store 对象 + 订阅（视图只读快照）

- 在 `app.core.js` 把内存状态收敛为一个 `store`：`getState()` 返回当前快照，`setState(patch)` 统一入口，`subscribe(fn)` 通知渲染。
- 迁移期保留全局别名作为只读 getter（`Object.defineProperty`），**禁止新增直接赋值**；每迁移一个视图跑一遍 e2e。
- 路由渲染改为订阅驱动：`store.setState → 通知 → route()`，取代事件处理器里散落的 `renderX()` 调用。
- 验收：全部 e2e 通过；新增单元测试覆盖 setState / subscribe；视图文件中不再出现对全局数组的 `.push` / 直接赋值。

### 阶段 2：写入契约（消除假成功）

- `persist*()` 返回 Promise；UI 在 resolve 后提示“已保存”，reject 时提示并保留表单供重试。
- `pushJSON()` 已有有序队列与入队快照，保持；补“队列空 → 才允许导出/关闭”的守卫，避免导出漏掉最后一笔。
- JSON 备份恢复改走 `POST /api/import` 单事务接口（服务端已实现原子导入与格式校验），替换前端多次 PUT 的拼接流程。
- 验收：注入网络失败用例，UI 不报假成功；恢复导入中途失败时数据库零变更。

### 阶段 3：schema 版本 + 迁移前快照演练

- 引入 `PRAGMA user_version`，迁移函数按版本顺序执行、保持幂等；main 已先备份再迁移，补一次“从旧版本备份恢复”的演练脚本。
- 验收：构造 v1 库升级到当前版本，数据不变；升级失败时可用迁移前快照还原。

### 阶段 4：多标签页乐观并发（确有需求再做）

- `/api/state`、`/api/labs` 加 revision；写入带 `If-Match`，冲突返回 409，前端提示刷新合并。
- 验收：两个标签页交替编辑不产生静默覆盖。
