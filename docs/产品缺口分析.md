# 个人健康档案 · 产品缺口分析

> 来源：产品经理审阅（已读 README、使用指南、`docs/HANDOFF.md`、各主题 `.md`/`.html`、`assets/*`、`server/health_server.py`）＋ 对 `data/health.db` 的只读实查核对。
> 本文为只读分析的产出，未改动任何档案文件。
> 当前形态：静态 SPA（`index.html`）＋ 本地 SQLite 服务（`server/health_server.py` → `data/health.db`）＋ OCR 识别服务 ＋ 多主题档案视图。

## 一句话结论

骨架已相当完整（SPA + SQLite + OCR + 多主题视图），**真正的短板不在功能数量，而在「内容完整度」和「数据一致性 / 安全」**。最危险的三个问题：

1. **数据双轨、结论过期**：DB 里已有异常化验，但「健康问题总表」仍是过期静态结论；
2. **无版本安全网**：全部改动未做版本提交；
3. **健康库单副本、无备份**：`data/health.db` 只此一份，误删即永久丢失。

## 数据核对（只读实查）

- `data/health.db`（73,728 字节）表与行数：`body=1`、`labs=45`、`meta=1`、`reports=5`、`todo=0`、`weights=2`。
- `labs` 列：`id, date, category, name, value, unit, low, high, source, note, report_id` —— **无定性结果字段**（尿蛋白、隐血等“阴/阳、+−”无法落库）。
- `todo` 表 **0 行** → 复诊待办页无任何实例；“添加待办”为只读。

## 一、缺失的内容 / 模块

| 优先级 | 缺口 | 建议 |
|---|---|---|
| P0 | 过敏史 / 家族史 / 手术住院无结构化档案 | 就医与急救刚需，做成个人资料里的结构化必填块 |
| P0/P1 | 个人资料 10 项空白：姓名、出生日期、腰围、睡眠作息、吸烟饮酒、饮食外卖、过敏、手术住院、家族史、当前全部用药 | 做成“必填清单 + 完成度进度”，逐项补齐（全档元数据底座） |
| P1 | 主题大量空壳：`鼻炎.md`、`雄脱.md`、`肝肾功能检查.md` 为空文件；牙齿、甲沟炎、脚气、尿频尿急仅有目录；鼻中隔偏曲仅 4 行 | 每主题定“最小可用档案”模板（主诉/诊断/诱因/当前处置/复诊节点），空壳标“待补” |
| P1 | 就诊记录**只有模板、零实例** | 先补最近 3–5 次真实就诊做样板，验证字段够用再入库 |
| P1 | 无**生命体征自测**模块（血压/心率/体温/血氧/血糖） | 增加“体征”视图，慢病/减重追踪核心数据 |
| P1 | 无**症状日记 / 不适记录**（干眼、鼻炎、踝痛等主观症状无处按日记录） | 轻量“症状日志”（日期+部位+程度+诱因），不为每个病单独建页 |
| P1 | 减重侧**执行数据几乎为空**（每日记录仅 10-27 一行、餐次全“未记录”，体重仅 2 条、围度 1 条） | 把“每日记录/每周复盘”做成可填可回看的闭环，否则规则文档成空中楼阁 |
| P1 | 小米手环/体脂秤**原始 CSV 已落盘但完全未接入**（睡眠/饮食/运动/体重/体脂） | 先做“体重/体脂/睡眠”三项 CSV 导入，现成高价值数据、成本低 |
| P2 | 报告照片 / DICOM 原件**页面无查看入口**（死链） | 检验记录/时间线里挂“查看原件”，先能打开图片/PDF |
| P2 | 全部检验记录(`#/labs-all`)**侧栏无入口**，用户找不到 | 并入“检验指标”或补侧栏入口 |

## 二、数据维度 / 字段缺口

| 优先级 | 缺口 | 建议 |
|---|---|---|
| P1 | **定性检验结果无法记录**（尿蛋白、隐血等“阴/阳、+−”被跳过、不落库、不进趋势） | labs 加 `qualitative` 字段（结果类型+结果值） |
| P1 | **异常标志未结构化**（无统一 ↑↓/H/L 标记与来源） | 落库派生 `flag(H/L/N)`，总览/趋势/问题总表统一消费 |
| P1 | **体重/体脂字段太少**：weights 仅 kg/腰围/备注，无体脂率、肌肉量、BMI、内脏脂肪、基础代谢 | 字段对齐小米体脂秤导出，直接承接 CSV |
| P1 | **整类实体缺表**：vitals、symptom、allergy、vaccine、visit（就诊实例）、family_history、surgery、medication（含剂量/频次/起止） | 按就医刚需排序建库：allergy、visit、medication 先行 |
| P2 | 检验元数据缺失：无采集时间(时分)、无机构/方法学、无参考区间来源 | 至少补“机构+采集时间”，跨院对比才说得清 |
| P2 | reports 缺就诊属性：就诊类型(门诊/急诊/住院)、科室、医生、费用、异常项摘要 | 补科室/医生/类型三项 |
| P2 | 围度只有胸/腰/臀，缺大腿、上臂、颈围 | 按需加 2–3 个围度 |

## 三、功能与体验短板

| 优先级 | 短板 | 建议 |
|---|---|---|
| P1 | **核心内容不可页内编辑**：健康问题、时间线、用药须改 `.md`+`data.js` 再手工同步（数据腐化根源） | 至少让“健康问题状态/复诊待办/用药”支持页内增改 |
| P1 | 复诊待办页“添加待办”**实际不新建**（todo 表 0 行，只读还误导） | 做成真新增，或明确标“只读” |
| P1 | **无任何提醒/通知**（复诊、用药、记录打卡、备份） | 打开即提示到期项，首页红点提示复诊/用药 |
| P1 | 定性结果进“跳过”**静默丢弃**异常 | 与定性字段一起修，跳过项显式提示“未纳入” |
| P1 | **无设备 CSV 导入向导**（有报告导入，无健康设备数据导入） | 复用现有 import 框架加“设备数据”入口 |
| P2 | 报告/影像无查看器（原件与数据割裂） | 先能打开图片/PDF 原件 |
| P2 | 无整档打印/PDF 导出给医生（仅有单页打印样式） | 做“就诊前导出摘要”（近期异常+用药+待复诊）一页纸 |
| P2 | 移动端仅局域网访问、无真实移动工作流 | 短期先把关键页做响应式可用 |
| P2 | 无空状态引导 / onboarding | 空视图给“下一步该填什么”引导卡 |
| P2 | 可维护性债：`assets/app.js` 单文件约 2851 行、解析规则硬编码、`.md→.html` 手工同步、无 CI | `.md→.html` 加自动构建，app.js 按视图拆模块 |

## 四、风险点（最重要）

| 优先级 | 风险 | 建议 |
|---|---|---|
| **P0** | **数据双轨、结论过期（最危险）**：DB 已有 45 条化验（含 eGFR 77.7 等异常），但 `健康问题总表.md` 与 `data.js`（2026-10-27）仍写“肝肾功能暂无化验结果、不能判断正常异常”——用户看到的是**错误结论** | 问题总表/总览改为**从 DB 自动派生**，禁止手写“暂无结果”这类必然过期的判断 |
| **P0** | **无版本安全网**：全仓仅 1 次初始提交，约 40 项改动未提交 | 立刻做一次基线提交，之后按功能小步提交 |
| **P0** | **单副本无备份**：`data/health.db` 只此一份、无自动备份、无导出提醒 | 服务启动时自动滚动备份（每日 1 份保留 N 天）+ 导出提醒 |
| **P0/P1** | **临床误判风险叠加**：静态摘要过期 + 定性项丢弃 + 跨院参考区间无归一化提示 | 趋势图/总表标注“参考区间来源/机构”，差异给警告 |
| P1 | **服务单点、降级割裂**：服务崩溃或未启动即落 localStorage，两套数据不互通，易“录了但找不到” | 加最小守护/自启；降级时强提示“当前为浏览器存储模式，非主数据” |
| P1/P2 | **隐私 / PHI 明文**：SQLite 明文、无访问控制、仅监听 localhost 但局域网可能可达、localStorage 残留 | 确认绑定 127.0.0.1，导出文件加密或提醒妥善保管，README 明示 |
| P2 | **可维护性债**：见上「功能与体验短板」末条 | 引入 `.md→.html` 自动构建（现成 `Tools/生成HTML档案.cjs`）+ 拆分 app.js |
| P1 | **内容长期腐化**：空壳主题、“暂无结果”类结论不随数据更新 | 引入“档案完整度”看板，让空壳和过期结论可见、可追 |

## 如果只做三件事（推荐排序）

1. **修“数据一致性”（风险 P0）**——让“健康问题总表 / 总览”从 DB 自动生成，把肌酐/尿酸/eGFR 这些**已存在的异常**真正呈现。这是“档案有没有用”的生死线，工作量不大。
2. **修“数据安全”（风险 P0）**——先提交一次建立基线，再加自动备份。丢不起，成本极低。
3. **补“个人资料与就医刚需字段”（P0/P1）**——过敏、手术住院、家族史、当前用药做成必填完成度清单。

其余 P1（定性检验、体征与症状模块、空壳主题、CSV 接入、页内可编辑、提醒）建议打包为「V1.1 内容与可用性冲刺」；P2 留到下个周期。
