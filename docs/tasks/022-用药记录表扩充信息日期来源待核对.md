# 022 用药记录：medication 表扩充信息日期/来源/待核对字段

- **优先级**：P1（数据完整性）
- **问题**：用药记录 md 里有「信息日期 / 来源 / 当前状态·待核对」三类信息，但 `medication` 表只有 `note` 一个大字段，导致这些结构化维度被压成一段长文本，既不好筛选也不能区分「已确认」与「待核对」。
- **目标**：给 `medication` 表增加三列并在前后端贯通，把用药记录结构化入库。
- **范围**：
  - DB：`medication` 增 `info_date`（信息日期）、`source_ref`（来源：原始档案 md + 行号）、`to_verify`（待核对事项）三列；`init_db` 幂等 `ALTER TABLE ... ADD COLUMN`，禁 DROP。
  - 后端 `server/health_server.py`：`get_all()` SELECT 带 camelCase 别名 `infoDate/sourceRef/toVerify`；`replace_history()` INSERT 三列。
  - 前端：`normMedication` 增加三字段白名单截断；用药表单新增三个输入；`medicationsTableHTML` 在药名下展示信息日期/来源/待核对。
  - 数据回填：按 `用药记录.md` 逐条回填现有 5 条（海露/磺胺冰片膏/全氟乙基辛烷/环孢素/思源）。
- **验收**：`/api/all` 的 medications 含三新字段且 5 条都有值；PUT `/api/history` 往返持久化正确；页面 200 / health.db 404；数据仍在本地 `data/health.db`，不进 git。
- **关联**：用药记录 md `private_data/record/medications/用药记录.md`；隐私上 health.db 与 private_data 均已被 .gitignore 忽略，不上传。
